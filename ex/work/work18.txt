연계 서버 도입 시 이점
송수신 시스템의 느슨한 결합 : 프로토콜, 데이터 형식 변환을 연계 서버가 담당, 시스템은 자신의 본래 업무 로직에만 집중할 수 있다.
중앙 집중식 통합 관리 : 연계 서버가 메시지 라우팅, 인증, 암호화 및 오류 재처리를 통합수행하므로 새로운 시스템 연계 시 연계 서버의 
어댑터 설정 변경만으로 손쉽게 확장 가능

[문제 7] 연계 방식(실시간 vs 배치) 선택 및 트레이드오프 분석
대용량 사용자를 보유한 금융 시스템에서 '실시간(Real-time) API 연동'과 '주기적 일괄 처리(Batch) 연동'을 적절히 혼용하려 한다. 실시간 처리와 배치 처리를 결정할 때 고려해야 할 핵심 요소 2가지를 설명하고, 모든 연계를 실시간 방식으로 처리했을 때 운영 DB 및 네트워크에 미치는 부작용을 기술하시오.

데이터 적시성 : 즉각적인 결과 확인이 필요한 업무는 실시간 방식을, 시차 반영이 허용되는 업무는 배치 방식을 선택한다.
네트워크 부하 : 처리하려는 데이터의 건수와 크기를 고려하여, 대용량 트랜잭션 발생 시 운영 DB 부하 완화를 위해 배치 처리 선택

전체를 실시간 처리로 선택하면, 대용량의 연계 데이터 요청이 몰릴 경우 운영 DB에 대량의 트랜잭션과 락이 발생하여 DB 성능 저하 및
메모리 부족 현상이 발생한다. 또한 네트워크 과부하로 연계 타임아웃 오류가 빈번해지며 전체 서비스 불능 상태에 빠질 수 있다.

[문제 8] 인터페이스 테이블(I/F Table)의 임시 저장소 역할과 트랜잭션 보장
송신 시스템에서 수신한 연계 데이터를 수신측 운영 DB의 업무 테이블에 직접(Direct) INSERT 하지 않고, 중간 저장 영역인 인터페이스 테이블(I/F Table)을 거쳐 단계적으로 반영하는 이유를 '데이터 정합성' 및 '오류 복구(재처리)' 관점에서 논하시오.
데이터 정합성 보장 : 수신된 데이터가 업무 db의 스키마 및 업무 규칙을 준수하는지 검증하는 버퍼 역할을 한다. 중간 검증 과정 없이 직접 적재 시
잘못된 포맷이나 코드값으로 인해 기존 업무 db의 데이터 오염을 초래할 수 있다.
오류 복구 및 트랜잭션 독립성 : 수신측 업무 DB 적재 로직 중 예외가 발생하더라도 인터페이스 테이블에 원래 전달 받은 데이터 원본과
원천 로그가 보존되어 있으므로 원인분석이 용이하다.

[문제 9] 연계 과정에서의 로그(Log) 설계와 장기 추적성
장애 추적을 위해 연계 서버에서 모든 송수신 내역을 로그로 기록하고 있다. 단순 성공/실패 여부만 기록하는 로그 수준을 넘어, 분산 환경에서 특정 연계 건의 전체 이동 경로를 단일 ID로 추적하기 위해 도입해야 하는 로그 기록 요소를 설명하고, 로그가 SLA(Service Level Agreement) 준수 검증에 어떻게 활용될 수 있는지 서술하시오.
추적성을 위한 로그 요소 : 고유 Trace ID를 발급하여 송신 -> 연계 서버 -> 수신 시스템으로 이동하는 전체 흐름동안 유지하고,
각 단계별 타임 스탬프 및 처리 상태를 함께 기록해야 한다.
SLA 준수 검증 활용 : 로그에 기록된 '송신 시작 시간'과 '수신 시스템 업무 DB 반영 완료 시간'간의 차이를 분석하여 연계 구간별 지연시간을 측정한다.
속도를 만족하는지 검증하고, 처리 지연을 유발하는 병목구간을 찾아내어 시스템 구조 개선의 근거로 활용할 수 있다.

[문제 10] 이벤트 기반 통합(Event-driven Integration)과 메시지 큐 활용
온라인 쇼핑몰에서 고객이 '주문 완료'를 할 때, 재고 차감, 결제, 배송 요청, SMS 발송, 알림톡 전송 등의 연쇄 작업이 일어난다. 이를 '동기식(Synchronous) API 호출'로 처리할 때의 문제점과 비교하여, '메시지 큐 기반의 비동기 이벤트 처리' 구조로 변환했을 때 수신 시스템 장애 상황에서 얻을 수 있는 시스템 안정성 효과를 설명하시오.
동기식 호출의 문제점 : 송신 시스템이 모든 하위 시스템의 처리가 완료될 때까지 대기해야 하므로 사용자 응답속도가 현저히 느려진다.
후속 시스템 중 하나라도 장애 발생 시 전체 주문 트랜잭션이 실패하는 연쇄 장애가 발생한다.

메시지 큐 기반 비동기 처리의 효과
- 주문 시스템은 주문 이벤트가 발생한 후 즉시 응답을 완료할 수 있어 시스템 간 결합도가 낮아진다.
- 배송/SMS 시스템에 장애가 발생하더라도 발행된 메시지는 메시지 큐에 안전하게 대기상태로 보관된다. 수신 시스템이 복구된 이후
큐에서 메시지를 순차적으로 꺼내어 처리할 수 있으므로, 데이터 손실이나 서비스 전체 중단 없이 시스템의 가용성과 높은
결함 허용성을 확보할 수 있다.
