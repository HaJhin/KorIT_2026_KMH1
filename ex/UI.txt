UI(User Interface) : 사용자 인터페이스
- 사용자가 제품과 상호작용하는 시각적인 요소와 디자인을 의미한다.
- 버튼 디자인, 아이콘, 색상 구성 등이 UI의 요소에 해당한다.
- UI는 사용자가 소프트웨어를 어떤 관점에서 보고 어떻게 조작하는지에 중점을 둔다.

UX(User eXperience) : 사용자 경험
- 사용자가 소프트웨어를 사용하며 느끼는 전체적인 경험을 의미한다.
- 예를 들어 웹을 사용하면서 느끼는 만족도, 편의성, 효율성 등이 UX에 해당한다.
- UX는 사용자가 소프트웨어를 통해 무엇을 얻고 느끼는지에 중점을 둔다.

UI/UX 구성요소
UI 구성 요소
- 시각적 디자인 : 색상, 타이포그래피, 레이아웃, 아이콘 등 사용자가 화면에서 보는 모든 요소
- 상호작용 디자인 : 버튼 클릭, 스와이프 등 사용자의 조작에 대한 반응
- 정보 구조 : 콘텐츠의 구성 및 분류
UX 구성 요소
- 사용성 : 사용자가 소프트웨어를 얼마나 쉽게 이용할 수 있는지 정도
- 유용성 : 소프트웨어가 사용자의 요구사항을 얼마나 충족하는지 정도
- 매력도 : 소프트웨어가 사용자에게 얼마나 매력적인지 정도
- 접근성 : 다양한 사용자가 소프트웨어를 얼마나 쉽게 이용할 수 있는지 정도
- 신뢰성 : 소프트웨어에 대한 사용자의 믿는 정도

UI/UX의 관계
- 서로 밀접하게 관련이 있긴 하다.
- UX를 위해선 좋은 UI가 필수지만, 좋은 UI가 항상 좋은 UX를 보장하지는 않는다.
- 예) 멋진 버튼이 있어도 사용하기가 불편하면 좋은 UX라고 할 수 없다.
- 사용하기 편리한 화면이라도 디자인이 매력적이지 않다면 좋은 UX를 제공하기 어렵다.
- UI와 UX는 서로 보완하며 사용자의 만족도를 높이는데 기여한다.

UX/UX 표준
- 과거에는 개발자나 기업의 관점에서 시스템을 설계하는 경우가 많았다.
- 하지만 최근에는 사용자의 편의성과 만족도가 중요해지면서 사용자 중심의 UI/UX 설계가 요구되고 있다.
- 개발자마다 서로 다른 방식으로 화면을 설계하면 사용자가 혼란을 느낄 수 있다.
- 시스템마다 UI가 다르면 매번 사용 방법을 새롭게 학습해야 한다.
- 이러한 문제를 줄이기 위해 UI/UX 설계 시 공통적으로 참고할 수 있는 기준을 마련한 것이 UI/UX 표준이다.

UI/UX 표준이 필요한 이유
1. 일관성 있는 사용자 경험 제공
- 공통된 설계 기준을 적용하면 사용자는 새로운 시스템도 쉽게 사용할 수 있다.

2. 사용성 향상
- 사용자는 시스템을 배우는 시간을 줄이고 원하는 작업을 더 빠르게 수행할 수 있다.
상품 검색 - 상품 선택 - 장바구니 - 결제
- 이러한 표준적인 구조는 사용자가 쉽게 적응할 수 있도록 돕는다.

3. 개발 품질 향상
- 표준을 적용하면 검증된 설계 원칙을 사용할 수 있으므로 품질이 향상된다.

4. 유지보수가 용이하다
- 화면 구조와 설계 기준이 통일되어 있기 때문에 기능 추가와 수정이 쉬워진다.

5. 접근성 향상
- 연령, 성별, 직무, 장애 여부와 상관없이 다양한 사용자가 시스템을 사용할 수 있도록 지원할 수 있다.

주요 내용
- 핵심은 사용자 중심 설계

2. 사용자를 설계 과정 전반에 참여시킨다.
- 사용자 중심 설계에서는 사용자가 단순한 평가 대상이 아니라 설계 과정의 중요한 참여자가 된다.
예를 들어 화면 시안을 제작한 후 실제 사용자에게 사용해보도록 하고 의견을 수집할 수 있다.
이를 통해 개발자나 디자이너가 미처 발견하지 못한 문제점을 확인할 수 있다.

3. 사용자 평가를 기반으로 설계한다.
- 설계자는 사용자의 의견과 사용성 평가 결과를 바탕으로 지속적으로 시스템을 개선해야 한다.

4. 반복적인 설계 과정을 수행한다.
- 사용자 중심 설계는 다음과 같은 반복과정을 거친다.
요구사항 분석 -> 프로토타입 제작 -> 사용자 평가 -> 개선 -> 재평가

5. 사용자 경험 전체를 고려한다.
- 단순히 화면 디자인만을 의미하지는 않는다.
- 사용자가 서비스를 처음 접하는 순간부터 사용을 종료하는 시점까지의 모든 경험을 포함한다.

6. 다양한 전문가가 협력하여 설계한다.
- 효과적인 사용자 경험을 제공하기 위해서는 여러 분야의 전문가가 함께 참여해야 한다.

개발자, 기획자, 품질관리 담당자, 사용자 연구 전문가

1. 소프트웨어 개발을 위한 화면 표준 및 지침을 확인한다.
국가기관에서 제공하는 지침을 수집하고 분석
국가기관에서 제공하는 공공 웹/앱 UI/UX 가이드라인을 수집하여 접근성, 정보 구조, 색상 및 타이포그래피 등 주요 항목을 파악한다.

- 국가기관의 공식 웹사이트에 접속한다
과학기술정보통신부 : 정보통신 정책 및 디지털 서비스 관련 지침을 제공
행정 안전부 : 전자정부 서비스 및 공공 웹사이트 구축 지침 제공
한국인터넷진흥원(KISA) : 웹 접근성 및 정보보호 관련 가이드 제공
공공누리 : 공공기관 컨텐츠 활용 및 표준 제공

- UI/UX 관련 키워드로 검색
각 기관의 자료실 또는 정책 자료 게시판에서 UI/UX 관련 자료를 검색한다.
제공된 지침은 문서나 가이드라인 목록을 확인하고 최신 버전의 문서를 우선순위로 확인한다.
	가이드 라인은 시간이 지남에 따라 개정될 수 있다.
	따라서 오래된 문서보다 최신 버전 문서를 우선적으로 검토해야 한다.
관련 지침이나 가이드라인 문서를 다운로드 받고 문서 개요 및 목차를 확인한다.

제공하는 지침이나 가이드라인의 접근성, 일관성, 색상 대비 등 핵심 항목을 발췌하여 정리한다.
- 자료의 주요 항목 선별 기준을 정의한다.
 접근성,일관성,색상 대비 등 어떤 항목을 중심으로 발췌할 것인지를 선정하고 불필요한 정보를 제외할 수 있도록 기준을 정의한다.
- 접근성과 관련된 항목을 정리한다.
 장애인 접근성 보장을 위한 명시적 지침을 요약하여 정리한다.
- 일관성과 관련된 항목을 정리한다.
 네비게이션 구성의 일관성, UI 패턴 동일성, 명칭 아이콘 버튼의 반복 사용 등에 관한 지침 내용을 확인하여 정리
- 색상 대비와 관련한 항목을 정리한다.
 최소 대비 비율과 같은 지침내용을 확인하여 정리한다.

공공기관 웹사이트/앱 사례에 적용된 가이드라인 요소를 분석한다.

- 선정한 웹사이트 또는 앱에 적용된 가이드라인 요소 분석을 위한 항목을 정리한다.

- 각 항목에 대해 직접 사용한 후 기준에 따라 준수 여부를 체크하고 가이드라인 기준 미달 사례를 수집한다.

0608

UI(UserInterface)
- 제품이나 소프트웨어와 상호작용할때 직접 보거나 조작하는 화면 요소
- 사용자가 눈으로 보거나 손으로 누르는 모든 구성 요소
UX(UserExperience)
- 사용자가 소프트웨어를 사용하면서 느끼는 전체적인 경험
- 서비스를 이용하면서 느끼는 편리함, 만족감, 효율성, 즐거움 등을 모두 포함한다.

UI 구성 요소
1. 시각적 디자인(Visual Design)
- 사용자가 화면에서 보는 모든 요소
- 색상, 글꼴, 아이콘, 이미지, 레이아웃
2. 상호작용 디자인(Interaction Design)
- 사용자의 행동에 대해 시스템이 어떻게 반응하는지 설계
- 좋은 상호작용 디자인은 사용자가 어떤 상태인지 쉽게 알 수 있도록 도와준다.
3. 정보구조(Information Architecture)
- 정보를 체계적으로 분류하고 배치하는 방법

UX 구성 요소
1. 사용성(Usability)
- 사용자가 얼마나 서비스를 쉽게 이용할 수 있는가
2. 유용성(Usefulness)
- 서비스가 사용자의 요구사항을 얼마나 잘 충족하는지 의미한다.
3. 매력도(Desirability)
- 서비스가 사용자에게 얼마나 매력적으로 느껴지는가
4. 접근성(Accessibility)
- 모든 사용자가 서비스를 이용할 수 있도록 만드는 정도
- 시각장애인, 청각장애인, 고령자, 색약 사용자 등도 서비스를 사용할 수 있어야 한다.
5. 신뢰성(Credibility)
- 사용자가 서비스와 정보를 얼마나 믿을 수 있는가

UI/UX의 관계
- 좋은 UI는 좋은 UX에 도움이 된다.
- 항상 좋은 UI가 좋은 UX는 아니다.

적용대상 : 사용자와 컴퓨터가 상호작용하는 모든 분야
- 소프트웨어(프로그램)
- 웹사이트
- 모바일 앱
- 디지털 기기

주요 내용 (사용자 중심 설계를 위한 6가지 원칙)
1. 사용자는 설계 과정 전반에 적극적으로 참여한다.
- 실제 사용자의 의견을 먼저 수집한다.
2. 사용자 중심 설계는 전체 사용자 경험을 고려해야 한다.
- 기능만 동작한다고 되는게 아니라 사용자가 느끼는 감정도 고려
3. 설계는 반복적으로 이루어져야 한다.
- 계속 테스트를 하고 수정해서 UI를 만들어나가야 한다.
4. 설계는 사용자와 소프트웨어 구축 목표 및 환경을 기반으로 한다.

3. 플랫폼별 디자인 가이드라인을 수집하고 분석한다.
3-1. 분석 대상 주요 플랫폼을 선정하고 특성 파악하기.
플랫폼 : 소프트웨어가 실행되는 환경
주요 플랫폼 종류
모바일, 웹, 데스크탑, 스마트워치, TV

- 플랫폼별 특징 쉽게 이해하기
모바일 : 스마트폰, 태블릿 환경, 손가락을 이용한 터치, 버튼이 너무 작으면 사용하기 힘듦
웹 : 크롬,엣지,사파리같은 브라우저 환경,PC,태블릿,스마트폰을 사용한 접속. 화면 크기에 따라 적절한 레이아웃 변경
데스크톱 : PC와 노트북에서 사용하는 환경, 키보드와 마우스 중심으로 조작, 화면이 크기 때문에 많은 정보를 한 번에 보여줄 수 있다.
스마트워치 : 화면이 매우 작다, 간단한 알림, 상태 확인, 빠른 조작 중심으로 설계
TV : 사용자가 화면에서 멀리 떨어져서 조작, 리모콘으로 조작하기 때문에 세밀한 조작이 어렵다.

3-2. 각 플랫폼별 공식 디자인 가이드라인 문서를 확인한다.
- 플랫폼마다 사용자가 익숙하게 느끼는 화면 방식이 다르기 때문이다.
- 가이드라인에서 확인할 내용
색상 : 서비스의 분위기와 정보 전달에 영향을 준다.
타이포그래피 : 글꼴, 글자 크기, 줄 간격 (글자가 너무 작으면 사용자가 내용을 읽기 어렵다.)
레이아웃 : 화면 배치 방식
컴포넌트 : 버튼, 입력창, 카드, 메뉴터럼 반복해서 사용하는 UI 요소
상호작용 : 사용자가 버튼을 누르거나 스와이프할때 시스템이 어떻게 반응할 지 결정

3-3. 플랫폼별 공통 요소와 차이점을 비교 분석한다.

- 비교할 주요 항목

- 실제 서비스에서 가이드라인이 어떻게 반영되었는지 확인하면 설계 감각을 키울 수 있다.
- 사례 분석 항목
화면 구조 : 정보가 어떻게 배치되어 있는가?
메뉴 구성 : 사용자가 쉽게 이동할 수 있는가?
버튼 스타일 : 버튼이 명확하고 누르기 쉬운가?
입력 방식 : 터치, 키보드, 마우스, 리모컨에 적합한가?
피드백 : 클릭이나 선택 후 반응이 명확한가?
접근성 : 글자 크기, 색상 대비, 보조 기능을 고려했는가

4. 기존 유사 응용 소프트웨어의 UI 설계 사례를 조사하고 분석한다.

4-1. 유사 응용소프트웨어를 선정하고 분석한다.
- 비슷한 서비스를 분석하면 어떤 메뉴 구조를 사용하는지, 어떤 화면 구성을 사용하는지, 사용자가 어떤 기능을 자주 사용하는지 파악할 수 있다.

ㄴ 메뉴 이동이 빠르다.
ㄴ 많은 기능을 정리할 수 있다.
ㄴ 작은 화면에서는 공간을 많이 차지한다.
ㄴ 모바일 환경에서는 사용하기 어렵다.

다크모드 사례를 분석하고 특성을 정리한다.
ㄴ 눈의 피로 감소
ㄴ 배터리 절약
ㄴ 어두운 환경에서 사용 편리
ㄴ 색상 설계가 어렵다
ㄴ 가독성이 떨어질 수 있다.

카드 레이아웃을 분석하고 특성을 정리한다.
ㄴ 정보 구분이 쉽다.
ㄴ 모바일 환경에 적합하다.(손가락으로 누르기 쉽고, 하나의 콘텐츠를 카드 단위로 구분하기 좋다.)
ㄴ 확장성이 좋다.
ㄴ 많은 정보를 한 번에 보기 어렵다.
ㄴ 공간을 많이 사용한다.(카드 하나가 차지하는 높이가 커서 한 화면에 여러 정보를 보여주기 어렵다.

모달(Modal) 사례를 분석하고 특성을 정리한다.
ㄴ 사용자의 집중을 유도한다.
ㄴ 중요한 정보를 강조할 수 있다.
ㄴ 너무 많이 사용하면 불편하다.
ㄴ 작은 화면에서는 공간이 부족하다.

4-3. 사용자 편의성과 UX 요소 비교 평가를 한다.

만족도 : 사용자가 만족하는가

통계 기능	그래프,차트

분류하는 이유
- 기능 유형에 따라 화면 설계 방식이 달라지기 때문이다.

입력기능 -> 입력창 필요
조회기능 -> 목록 화면 필요
통계기능 -> 차트 필요

5-3. 목표 응용 소프트웨어의 사용자를 식별하여 정의한다.
- 같은 기능이라도 사용자에 따라 필요한 화면이 다르다.
- 사용자 특성에 따라 UI 복잡도가 달라진다.
IT 활용 능력이 낮음 -> 단순한 화면 필요
IT 활용 능력이 높음 -> 다양한 기능 제공이 가능하다.

5-4. 사용자 유형별 사용 목적 및 기대 행동을 정의한다.
강사
사용목적
- 출결 입력
- 출결 확인

기대행동
출결을 입력한다.
학생 목록을 조회한다.

관리자
사용 목적
- 매출 확인
- 수강생 현황 확인

기대행동
- 통계 조회
- 보고서 출력

목적을 이해하면 필요한 메뉴와 화면을 결정할 수 있다.

5-5. 사용자 기기, 운영체제, 이용 시간대 등 사용자 환경을 분석한다.
사용자 환경 : 사용자가 서비스를 사용하는 환경
분석항목
기기(Device) : PC, 노트북, 태블릿, 스마트폰
운영체제(OS) : Windows, macOS, Android, iOS
이용장소 : 사무실, 학교, 집, 야외
이용시간대 : 업무 시간, 야간, 주말

예시
강사
기기 : PC
운영체제 : Windows
시간대 : 수업 전후

5-6. 사용자 경험상의 주요 고려사항을 도출한다.
- 사용자가 서비스를 사용할 때 느끼는 편의성과 만족도를 고려

클릭수 최소화 : 목표까지 도달하기 위해 많은 클릭은 피곤하다.
명확한 피드백 제공 : 클릭해도 반응이 없으면 저장 여부를 알 수 없다.
색상대비 확보 : 배경과 글씨가 구분이 잘 되도록 한다.
일관성 유지 : 저장 -> 파란색, 삭제 -> 빨간색 모든 화면이 동일해야 함
접근성 고려 : 대체 텍스트, 키보드 사용, 색약 모드 제공

5-7. 기능별 사용자 사용 시나리오 작성
- 사용자가 어떤 순서로 화면을 사용하게 되는가
- 사용 시나리오를 작성하면 어떤 화면이 필요한지, 버튼이 필요한지, 어떤 순서로 이동하는지 쉽게 파악 가능

6. 업무의 특성을 고려하여 UI 구성 요소 및 흐름 파악하기
6-1. 화면별 주요 구성요소인 버튼,폼,메뉴등의 목록 작성하기
- 각 구성 요소의 명칭, 기능, 위치 등을 정리하여 응용 소프트웨어의 각 화면에 포함된 UI 구성 요소를 식별하고 목록화한다.

6-2. 화면간 이동경로인 UI 흐름도를 작성한다.
- 사용자가 화면과 화면 사이를 어떻게 이동하는지 표현한 그림
- 사용자 이동 경로 : 사용자가 원하는 기능까지 몇 번 클릭하는지
- 화면 간 관계 : 현재 화면 -> 다음 화면
- 예외 상황 : 로그인 실패 -> 로그인 화면 유지

UI 흐름도를 작성하는 이유
- 화면 누락 방지
- 기능 누락 방지
- 개발 범위 파악
- 사용자 경험 개선

6-3. 핵심 기능인 상호작용 방식을 분석한다.
- 상호작용 : 사용자가 소프트웨어를 조작했을 때 시스템이 반응하는 과정
- 같은 기능이라도 상호작용 방식에 따라 사용자의 편의성이 크게 달라진다.

6-4. 디자인 일관성, 접근성, 사용성을 평가한다.
- 전체 UI에서 색상, 폰트, 버튼 형태 간격 등이 일관성 있게 적용되었는지 확인하고,
장애인이나 고령자 등도 쉽게 사용할 수 있는지 확인

6-5. 경쟁 소프트웨어의 UI 구성을 비교 분석
- 경쟁 서비스의 장점을 참고하고 단점을 개선하기 위해서
분석 항목
내비게이션 메뉴 : 사용자가 이동하는 방식
버튼 디자인 : 버튼 크기, 색상, 형태
입력 폼 : 사용자가 데이터를 입력하는 방식
사용자 흐름 : 작업 수행 과정

7. 사용자 면담 및 UI/UX 요구사항 수집
- 개발자나 디자이너가 생각하는 좋은 화면과 실제 사용자가 원하는 화면은 다를 수 있다.

7-1. 사용자 면담 또는 설문 대상자를 선정
- 시스템 구축 목표와 관련된 주요 사용자 그룹을 정의
- 사용자 그룹별 특성과 사용 목적을 파악
- 설문 대상자의 표본 크기와 선정 기준을 확정
- 설문 참여자 모집 및 일정 조율(이메일,문자,전화,사내 공지)

7-2. 면담 질문지 또는 설문지를 작성하고 계획을 수립한다.
- 면담/설문 목적과 목표를 명확하게 정의한다.
목적예시 : 현재 시스템의 불편사항 파악, UI 개선 요구사항, 사용자 만족도
목표예시 : 사용자 만족도 80% 이상 달성

- 질문의 초안을 작성한다.
기본정보 : 연령대, 사용기기, 사용 경험
현재 사용 경험 : 현재 UI 만족도, 자주 사용하는 기능, 불편한 화면
UI 개선 요구사항 : 버튼크기, 폰트크기, 메뉴이동 편의성
전반적인 개선 방향 : 가장 먼저 개선해야할 사항

- 질문의 유형을 정의한다.
객관식
주관식
혼합형 질문

설문지/면담 질의서 템플릿을 작성한다.
- 면담/설문 계획을 수립한다.

7-3. 면담/설문을 사전에 검증하여 수정보완한다.
- 내부 검토를 통해 질문 내용의 적절성을 평가한다.
ㄴ 질문이 명확한지?
ㄴ 중복 질문은 없는지?
ㄴ 빠진 질문은 없는지?
- 소수의 사용자에게 파일럿 면담/설문을 진행한다.
ㄴ 파일럿 조사 : 실제 조사 전 소규모로 먼저 테스트 하는 것
- 이해하기 어려운 질문, 중복 항목, 누락된 질문을 파악

7-4. 사용자 대상 면담 및 설문을 진행한다.
- 조사 목적과 일정을 공지한다.
- 정의한 면담 공식에 따라 면담을 수행한다.
- 설문을 진행할 경우 온라인 링크 또는 오프라인으로 설문지를 배포한다.

7-5. 기능 요구사항과 UI 개선 요구사항을 구분한다.
- 수집된 응답 내용을 기능/디자인으로 분류한다.
- 기능 개선 요청과 UI 개선 요청으로 태깅한다.
- 분류 기준과 에시를 작성한 후 데이터를 정리한다.

7-6. 유사 서비스 등에서 발생한 반복적 불만/요구사항의 우선 순위를 도출한다.
- 경쟁사 및 유사 서비스의 의견을 조사한다.
- 반복적으로 나타나는 불만 사항을 정리한다.
- 발생 빈도와 영향도에 따른 우선순위를 문서로 작성한다.
- 우선순위에 따른 개선 아이디어를 도출하고 보고서를 작성한다.

8. UI 요구사항을 도출하고 정리한다.
8-1. 수집된 요청 사항과 유사 서비스 등에서 발생한 불만 사항 등을 분석하여 결과를 통합한다.
- 사용자 설문, 면담, 로그 데이터 등에서 수집된 요청 사항을 목록화한다.
- 유사 서비스 리뷰 및 피드백 데이터를 수집한다.
- 중복 유사 요청 사항을 그룹핑하여 항목을 정리한다.
- 분석 결과를 통합 보고서로 작성한다.

8-2. 사용 목적과 시나리오별 UI 요구사항을 도출한다.
- 사용자 그룹별 사용 목적을 분석한다.
- 대표 사용 시나리오를 작성한다.
- 시나리오별 필요한 UI 구성 요소를 도출한다.
- 기능 흐름을 분석하여 UI 요구사항을 식별한다.

8-3. 기능 요구사항과 비기능 요구사항을 분류한다.

8-4. UI 요구사항에 고유 ID를 부여하고 설명을 작성한다.

8-5. 요구사항의 우선순위와 난이도, 중요도 기준을 정의한다.

8-6. UI 요구사항명세서를 작성한다.
