실제 서비스는 많은 사람들이 로그인을 해서 사용하기 때문에 인증 매커니즘을 구현을 해야한다.

인증
- 사용자가 누구인지 확인하는 과정
- 사용자 아이디와 비밀번호
- 다중요소 인증(sms, email)
- 생체인증(지문, 안면 인식)
- 소셜 로그인(페이스북, 구글, 네이버, 카카오)

인가
- 사용자가 인증된 후에, 그 사용자가 무엇을 할 수 있는지 결정하는 과정
- 특정 자원이나 기능에 접근할 수 있는 권한을 부여하는 절차

Basic 인증
- Todo 프로그램은 로그인을 제외하면 상태를 유지해야할 이유가 없다.
- 상태가 없는 웹 애플리케이션에서 인증을 구현하는 방법은 모든 HTTP 요청에 아이디와 비밀번호를 같이 보내는 것이다.
- 아이디와 비밀번호를 Base64 인코딩하여 HTTP 요청 헤더에 포함한 뒤 요청을 보낸다.
- 서버는 데이터를 받아서 디코딩하여 사용자가 인증할 수 있는지 확인하고, 자격이 유효하면 요청한 자원에 접근을 허용한다.

토큰 기반 인증
사용자가 인증에 성공한 후 토큰을 발급받아, 이를 사용해 서버와의 통신에서 인증을 처리하는 방식
- 이 방식은 세션 기반 인증과는 달리, 서버에 사용자의 상태를 저장하지 않고, 토큰을 통해 인증을 관리하기 때문에 무상태 방식으로 작동한다.
- RESTful API와 같은 분산 시스템에서 많이 사용된다.

토큰
- 사용자를 구분할 수 있는 문자열
- 서버가 자기만의 규칙으로 토큰을 만들어준다.

서버가 사용자 인증
- id랑 비밀번호를 확인하여 사용자가 올바른 자격을 가지고 있는지 확인

토큰 발급
- 인증에 성공하면, 서버는 사용자의 정보 또는 권한을 포함한 토큰을 생성하여 클라이언트에게 반환한다.
- 이 토큰은 주로 JWT(JSON Web Token) 형식으로 사용한다.

클라이언트가 토큰을 저장한다
- 브라우저에 저장을 한다.

토큰을 포함해 요청을 보낸다.
- 클라이언트는 서버에 요청을 보낼때마다 이 토큰을 HTTP 요청 헤더에 포함시켜 인증을 처리한다.

서버가 토큰을 검증
- 서버는 클라이언트로부터 전달받은 토큰이 유효한지 확인한다.
- 토큰이 유효하다면, 서버는 요청을 처리하고 필요한 자원에 접근을 허용한다.

응답 반환
- 서버는 클라이언트에게 요청된 데이터를 반환하거나, 필요한 처리를 수행한다.

JWT
- JSON 형식으로 사용자의 정보를 저장하고 서명을 통해 토큰의 무결성을 검증하는 토큰 기반 인증 방식

JWT는 세 부분으로 나뉜다.
1. 헤더
2. 페이로드
3. 서명
이 세 부분을 Base64 URL 인코딩으로 인코딩한 후 마침표로 구분해 하나의 문자열로 합쳐진 것이 JWT이다.

서명(시그니쳐)헤더와 페이로드 Base64로 인코딩한 다음 비밀키와 함께 선택한 알고리즘을 사용해 만든 값
ㄴ 시그니쳐는 토큰이 위변조 되지 않았는지 검증하는 역할을 한다.

시그니쳐가 중요한 이유는, 클라이언트가 JWT를 서버에 보낼 때 서버는 시그니처를 다시 계산하고, 클라이언트가 보낸 시그니처와 비교해서
토큰이 변조되었는지 확인할 수 있기 때문이다

아이디와 비밀번호를 사용한 Basic 인증

HTTP의 특성
무상태(stateless) : 이전 통신을 기억하지 않는다.
- 매 요청마다 인증정보를 함께 전달해야한다.
- 개인정보가 유출될 수 있다.
회원가입
로그인

토큰 기반 인증
- 사용자가 인증에 성공한 후 토큰을 발급받아, 서버와의 통신에서 인증을 처리하는 방식
- 토큰은 클라이언트의 브라우저에 저장이 된다. (자동로그인, 아이디 기억)

JWT(JSON Web Token)
- JSON 형식으로 사용자 정보를 저장하고 서명을 통해 토큰의 무결성을 검증하는 방식

구조
헤더 : 해싱 알고리즘, 토큰의 타입
페이로드 : 사용자 또는 시스템 관련 정보
서명 : 헤더와 페이로드를 Base64로 인코딩한 뒤 비밀키로 암호화한 문자열

JWT 토큰 생성 및 반환 구현
- 유저 정보를 바탕으로 헤더와 페이로드를 작성하고 서명한 뒤 토큰을 반환

JJWT 라이브러리
- JWT 토큰을 생성하고, 서명하고, 파싱하고, 검증해주는 기능을 가지고 있다.
JJWT-API : 개발자가 사용하는 JWT API 제공
JJWT-impl : JWT 기능의 실제 내부 구현체
JJWT-GSON : JWT의 JSON 직렬화/역직렬화를 Gson으로 처리

토큰을 발급해주는 시점
- 로그인을 할때 같이 발급

스프링 시큐리티 프레임워크
- 스프링 기반의 어플리케잇녀에서 인증과 인가를 처리하기 위한 강력한 보안 프레임워크

필터 기반 아키텍쳐
- 요청이 컨트롤러에 도착하기 전에 여러 보안 검색대를 통과하도록 만든 구조
- Todo에 대한 CRUD 작업을 할 때 검사를 진행한다.
- 로그인을 한 사람인가?
- JWT를 가지고 있는가
- 토큰이 유효한가?
- 만료되지는 않았는가?
이런 검사를 컨트롤러 앞에서 처리하는 역할을 Filter가 담당할 수 있다.
스프링 시큐리티는 여러개의 필터를 순서대로 연결하여 사용할 수 있다.
연결된 필터를 필터체인이라고 부른다.

OncePerRequestFilter : HTTP 요청 1번당 필터 로직이 한 번만 실행되도록 도와주는 Spring 필터 기반 클래스

doFilterInternal() : HTTP 요청이 들어오면 이 필터가 실행이 되고, 커스텀 필터를 만들 때 필터 처리 로직을 작성하는 메서드

HttpServletRequest request : 클라이언트가 보낸 HTTP 요청 정보
HttpServletResponse response : 클라이언트에게 보낼 HTTP 응답 정보
FilterChain filterChain : 다음 필터로 요청을 전달하는 객체

클라이언트 쪽에서 fetch()로 요청을 보낼떄 header에 토큰을 실어서 보낸다.
fetch("요청주소".{
	method : "GET",
	headers : {
		"Content-Type" : "application/json",
		"Authorization:"Bearer" + 토큰
	}
});

StringUtils.hasText(bearerToken) : 문자열 유효성 검증 메서드
- null인지 확인
- "' 빈 문자열인지 확인
- 공백만 있는지 확인
- 실제 문자열이 있는지 확인
