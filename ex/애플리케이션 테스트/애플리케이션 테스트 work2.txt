- 단위 테스트

문제 6. 구문 커버리지와 결정 커버리지 판단

다음 코드를 테스트한다.

public int calculateDiscount(int price) {

    int discount = 0;

    if (price >= 50000) {
        discount = 5000;
    }

    return price - discount;
}

다음 테스트 하나만 수행하였다.

입력 : 60000
결과 : 55000
문제

위 테스트 결과에 대해 다음 두 가지를 각각 판단하고 이유를 작성하시오.

구문 커버리지는 100%인가?
결정 커버리지는 100%인가?

결정 커버리지 100%가 아니라면 추가할 테스트 데이터를 하나 작성하시오.
구문 레버리지 = 100%
60000 입력 시 실행 가능한 구문이 모두 실행된다.
결정 커버리지 != 100%
조건식 결과중 거짓 결과를 실행하지 않았다.

버튼을 연속 클릭했을 때 중복 데이터 생성

비정상적으로 큰 주문 수량 입력
- 수량에 9999999같은 값을 입력한다.
- 허용되지 않는 입력에 대해 오류 처리 및 입력 제한이 정상적으로 수행되는지 확인한다.

문제 10. 요구사항 기반 테스트 케이스 종합 설계

온라인 교육 시스템에 다음 요구사항이 있다.

수강신청 요구사항
학생은 원하는 강좌를 신청할 수 있다.
하나의 강좌에는 최대 30명까지 신청할 수 있다.
이미 30명이 신청한 강좌에는 추가 신청할 수 없다.
동일한 학생은 동일한 강좌를 두 번 신청할 수 없다.
신청이 성공하면 수강신청 목록에 해당 강좌가 표시되어야 한다.

현재 상황은 다음과 같다.

강좌명 : Java Programming
현재 신청 인원 : 29명

학생 1001 : 해당 강좌 신청 이력 없음
학생 1002 : 해당 강좌 이미 신청함
문제

위 요구사항을 검증하기 위해 다음 3개의 테스트 케이스를 작성하시오.

정상 수강신청 : 현재 29명, 학생 1001은 미신청 -> 학생 1001이 수강 신청
-> 예상 결과 신청 인원 30명, 수강 신청 목록에 강좌 표시
최대 인원 초과
최대 인원 초과 테스트에선 이미 30명이 신청한 상태에서 추가 학생이 신청하면 시스템이 신청을 거부해야 한다.
중복 수강신청
중복 신청 테스트에선 이미 같은 강좌를 신청한 학생이 다시 신청할 경우 두번째 신청 등록 X
