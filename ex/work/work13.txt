[문제]
최근 연계 데이터 생성 및 추출 기술로 자주 활용되는 CDC(Change Data Capture)의 개념과 작동 원리를 서술하시오.
개념 : 송신 시스템 DB에서 데이터가 생성,수정,삭제되는 등 변경되는 부분만을 일시적으로 감지하여 추출하는 기술/프로그램


송수신 시스템 사이에서 어댑터(Adapter) 및 중계 서버 역할을 수행하는 API Gateway의 개념과 주요 기능 2가지를 서술하시오.
개념 : 서로 다른 서비스 및 시스템 간 API 호출을 단일 엔드포인트로 통합하여 중계하는 미들웨어/플랫폼이다.
주요 기능
- 트래픽 및 보안 관리 : OAuth2, JWT 등을 통한 인증/인가 및 접근 제어
- 메시지/프로토콜 변환 : JSON -> XML로 변환, REST -> gRPC

연계 메커니즘에서 **인터페이스 테이블(I/F Table)**의 개념과 이를 두는 주요 목적 2가지를 서술하시오.
개념 : 송/수신 시스템 사이에서 데이터를 직접 반영하지 않고 임시로 보관하기 위해 사용하는 중간 DB 테이블이다.
주요 목적
- 시스템 간 차이 완화 : 송수신 시스템의 스키마, 데이터 포맷, 전송 주기의 차이를 해소한다.
- 트랜잭션 및 오류 관리 : 데이터 전송 및 적재 중 오류 발생 시, 해당 데이터를 확인하고 실패건만 선택적으로 재처리 할 수 있도록
지원한다.

연계 메커니즘에서 **로그(Log)**의 개념을 정의하고, 로그 테이블에 필수적으로 기록되어야 하는 주요 항목 3가지를 쓰시오.
개념 : 송수신 시스템 간 데이터 연계 과정에서 발생한 모든 처리 이력과 결과를 시간 순으로 기록해둔 데이터
1. 송수신 일시
2. 인터페이스 DI 또는 테이블/파일명
3. 처리 단계 및 결과 상태
4. 처리 건수
5. 오류 코드 및 에러 메시지

시스템 간 데이터 연계 과정에서 발생하는 연계 오류의 정의를 쓰고, 발생 원인에 따른 연계 오류의 3가지 유형을 각각 서술하시오.
정의 : 서로 다른 시스템 간 데이터를 주고 받는 과정에서 데이터가 정상적으로 전송,수신,저장,처리되지 못해 발생하는 문제
연계 데이터 오류
연계 시스템 오류
연계 네트워크 오류 

장애 및 오류 로그(Log)의 개념을 서술하고, 시스템 운영 환경에서 오류 로그를 활용할 수 있는 방안 2가지를 쓰시오.
장애 발생 시점,이유,유형,대상 데이터 등을 시간순으로 추적할 수 있도록 기록해둔 흔적
1. 시스템 로그와 인터페이스 로그를 통합하여 조회하거나 장애 여부를 실시간으로 확인 가능
2. 장애 유형에 대한 통계를 추출하거나 재발 방지 대책 수립 가능

연계 장애 발생 시 신속한 원인 파악을 위해 수행하는 **'1차 확인(대시보드)'**과 **'2차 확인(로그 심층 분석)'**의 구체적인 수행 내용을 서술하시오.
1차 확인 :  모니터링 대시보드를 통해 장애 여부, 알람, 트렌드 확인
2차 심층 분석 : Trace ID, Correlation ID 기준 심층 조회

장애 로그를 '기록 단위' 기준으로 분류할 때, 시스템 로그, 연계(인터페이스) 로그, 데이터 로그의 개념적 차이를 각각 설명하시오.
시스템 로그 : 연계 서버 자체의 실행 접속 전송 상태 등 전반적 기록
연계 로그 : 송수신 데이터 단위의 전송, 변환, 처리 등 오류 기록
데이터 로그 : 개별 행, 데이터 필드 단위의 상세 오류 기록

최신 기술 환경인 MSA(마이크로서비스 아키텍처), AIOps, DevOps 중 하나를 선택하고, 해당 환경에서 요구되는 장애 처리 및 모니터링의 핵심 특징을 서술하시오.
DevOps : DevOps 환경에서는 장애를 100% 막는 것보다 얼마나 빠르게 탐지하고 복구하는가를 핵심 지표로 삼는다

[문제 2] 마이크로서비스(MSA) 기반 결제 연계 시스템의 장애 추적 및 재처리
[시나리오]

B 금융사는 기존 단일(Monolithic) 시스템을 MSA(마이크로서비스 아키텍처)로 전환했습니다. 사용자 결제 요청 시 [주문 서비스] -> [API Gateway] -> [결제 서비스] -> [외부 PG사] 순으로 API 연쇄 호출이 발생합니다.

어느 날 순간적인 네트워크 지연(Latency)으로 인해 [결제 서비스]에서 타임아웃 오류가 발생하면서 일부 거래 건의 데이터 적재가 실패했습니다.

[질문]

MSA 환경에서 이러한 장애가 일어났을 때, 단일 시스템 대비 장애 원인 추적이 어려운 이유와 이를 해결하기 위한 '분산 트레이싱(Distributed Tracing)'의 필요성을 서술하시오.
- 한 번의 사용자 요청을 처리하기 위해 여러 마이크로 서비스 간에 API 호출이 연쇄적으로 일어난다.
따라서 중간에 특정 서비스 하나가 멈추거나 지연되면 어디서 병목이나 오류가 발생했는지 찾기 어렵다.

OpenTelemetry, Jaeger, Zipkin 등을 활용하여 Trace ID 기반으로 송수신 데이터의 처리 흐름을 추적한다.

전송 실패된 거래 건들만 선별하여 다시 전송 및 반영하기 위해 '로그 테이블'에 반드시 포함되어야 하는 상태(Status) 관련 항목 2가지를 쓰시오.

■ [문제 3] 대용량 로그 수집으로 인한 서버 부하 방지 및 오류 로그 분류
[시나리오]

C 기업의 연계 서버 관리자 D 과장은 매일 발생하는 수백만 건의 연계 로그로 인해 DBMS 디스크 용량이 부족해지고, 로그 수집 작업으로 인해 연계 서버 성능이 저하되는 문제를 겪고 있습니다.

이에 D 과장은 기록 단위(시스템 로그, 연계 로그, 데이터 로그)에 따라 로그 수집 수준을 분리 설계하고, 머신러닝 기반의 이상 탐지 솔루션 도입을 검토 중입니다.

[질문]

다음 발생 상황 예시가 어떤 오류 로그 유형(시스템 로그, 연계 로그, 데이터 로그)에 해당하는지 각각 연결하시오.

(A) "연계 서버의 수신 디렉터리(C:/integration/send)가 존재하지 않아 프로세스 정지" : 연계 로그

(B) "인터페이스 IF-MEMBER-001 실행 중 수신측 포맷 변환(JSON -> XML) 실패" : 시스템 로그

(C) "MemberVO 객체의 memberName 필드가 빈값(Null)이어서 타깃 DB 적재 실패" : 데이터 로그

대용량 로그 수집 환경에서 인공지능/머신러닝을 활용하여 실시간으로 이상 징후를 탐지하고 원인을 자동 분석하는 최신 IT 운영 기술의 명칭을 쓰시오.
