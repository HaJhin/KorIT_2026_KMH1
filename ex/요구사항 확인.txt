요구사항 확인

1. 현행 시스템의 분석
- 새 시스템을 만들거나, 기존 시스템을 개선하기 위해 현재 사용중인 업무 방식, 프로그램,
데이터, 서버, 네트워크, 문제점 등을 조사하고 정리하는 활동

목적
- 새로운 시스템을 정확하게 만들기 위해 현재 상황을 이해한다.

문제점
1. 기존 업무의 흐름을 모른다면 필요한 기능을 빠뜨릴 수 있다.
2. 기존 데이터 구조를 모른다면 데이터 이전 시 오류 발생
3. 기존 시스템 연동을 모른다면 외부 시스템과 연결 실패
4. 사용자 불편 사항을 모른다면 새 시스템을 만들어도 만족도가 낮다.
5. 현재 원인을 모른다면 문제 해결이 아닌 단순 재개발이 된다.

현행 시스템 파악 절차
1단계 : 현행 시스템의 구성, 기능, 인터페이스 현황 파악
- 현재 시스템이 무엇으로 구성되어 있고, 어떤 기능을 제공하고, 다른 시스템과 어떻게 연결되어있는지 파악

시스템 구성현황 파악
- 현재 운영중인 시스템의 종류와 역할을 파악하는 것
ex)
시스템명 - 주요 사용자 - 역할
수강생 관리 시스템 - 관리자 - 수강생 등록,수정,조회
출결 관리 시스템 - 강사,관리자 - 출결 관리
상담관리 시스템 - 관리자 - 상담 이력 기록
결제 관리 시스템 - 관리자 - 수강료 결제 내역 관리
문자 발송 시스템 - 관리자 - 공지 문자 발송

기능 현황 파악
- 각 시스템이 제공하는 기능을 정리하는 것

수강생 관리 시스템
수강생 등록 : 신규 수강생을 등록
수강생 조회 : 학원에 다니는 수강생을 조회
수강생 수정 : 수강생의 정보를 수정
수강생 삭제 : 수강생의 정보를 삭제

인터페이스 현황 파악
- 시스템과 시스템이 데이터를 주고받는 연결 지점을 의미
- ex 결제 쇼핑몰
결제 API -> 주문번호, 결제금액, 결제 상태
택배사 API -> 주문번호, 주소, 송장번호
문자 발송 API -> 전화번호,메시지내용
이메일 API -> 이메일 주소, 인증 코드

2단계 : 현행 시스템의 아키텍처 및 소프트웨어 구성 현황 파악
- 현재 시스템이 어떤 구조로 만들어져있고, 어떤 소프트웨어를 사용하고 있는지 파악

아키텍처 현황 파악
- 현재 시스템이 어떤 구조로 만들어져 있는지 조사하는 일

소프트웨어 구성 현황 파악
- 현재 시스템이 어떤 소프트웨어를 사용하고 있는지 조사하는 일 

2단계 산출물
- 시스템 아키텍쳐 구상도
클라이언트부터 인프라까지 전체 구성을 한 눈에 파악할 수 있다.
- 소프트웨어 구성 목록
시스템을 구성하는 소프트웨어를 영역별로 정리한 목록
- 소프트웨어 버전 현황표
현재 사용버전, 최신 버전, 업데이트 상태를 한 눈에 파악할 수 있는 표
- 기술 스택 정리표
역할별 기술 스택을 목적,선택이유,대안까지 함께 정리한 표

3단계 : 하드웨어 및 네트워크 분석
- 현재 시스템이 운영되는 물리적 또는 클라우드 인프라 환경을 파악한다.

서버는 어디에서 운영되는지
서버 사양은 어떻게 되는지
네트워크는 어떻게 연결되어 있는지
방화벽이나 보안 설정은 어떻게 되어있는지

하드웨어 구성 현황 파악
- 서버,저장장치,백업 장비, 보안 장비 등의 정보를 정리하는 것
- 클라우드 환경이라면 EC2,RDS, S3같은 자원을 확인한다.

포트(port)
- 외부와 데이터를 주고받는 통로이자 접속 지점
SSL 인증서 (Secure Sockets Layer)  
- 웹사이트와 사용자 브라우저 간 데이터를 암호화하여 개인정보 노출을 막는 디지털 보안 솔루션
- 데이터 암호화
제 3자가 내용을 볼 수 없도록 보호
- 데이터 무결성
데이터가 전송 중 변조되지 않도록 보호
- 신원 인증
클라이언트가 접속하는 서버가 신뢰할 수 있는 서버인지 확인

캐시(Cache)
- 자주 사용하는 데이터나 값을 미리 복사해놓는 임시 장소를 가리킨다
- 저장공간이 작고 비용이 비싼 대신 빠른 성능을 제공한다.

- 발열이 심하고 너무 비싸져서 현실성이 없다.

클러스터(Cluster)
- 여러 대의 독립된 컴퓨터나 서버, 혹은 데이터들을 하나로 묶어 '단일 시스템'처럼 작동하게 만드는 기능 및 기술

SSMS(SQL Server Management Studio)
- Microsoft SQL Server를 관리하기 위한 전용 프로그램

Active Directroy
- windows 계정과 사용자 권한을 중앙에서 관리하는 시스템

.NET
- Microsoft의 개발 플랫폼
- C#이 포함된다.

튜닝
- 데이터베이스가 더 빠르고 효율적으로 동작하도록 최적화하는 작업
- 조회 속도 개선
- cpu 사용량을 감소
- 메모리 효율 증가
- 대량 동시접속 처리
- 디스크 I/O를 감소

실행계획 최적화 기능이 상대적으로 약함
DBMS는 SQL 실행 전에 "어떤 방식으로 데이터를 찾는게 가장 빠를까?"를 계산
이걸 실행 계획이라고 한다.
MySQL도 실행 계획이 있지만 Oracle과 같은 상용 DB보다 세밀함이 부족한 경우가 있다.

옵티마이저
- SQL 실행 전략을 자동으로 결정하는 엔진
- 오라클에 비해서는 세밀하지 못하다.

대규모 병렬처리에 약함
MySQL은 전통적으로 단순 웹서비스 중심, 읽기 위주의 구조에 강점이 있다.
그래서 초대형 데이터 분석에는 한계가 있었다.

Redis : 데이터를 메모리에 저장함

실시간 메시지 기능
pulish : 메시지 보내기
subscribe -> 메시지 받기

누군가는 메시지를 발행하고 누군가는 그 메시지를 구독해서 실시간으로 받는다.

채팅/실시간 알림/주식 시세/게임상태 동기화

4. 상호 호환성
- 어떤 운영체제에서 DBMS를 사용할 수 있는지 의미한다.

MySQL : windows, Linux
SQL Server : Windows 중심
Oracle : Linux,Unix 중심

드라이버 지원
예시 JDBC : Java 프로그램이 db에 접속하기 위한 기술
중요한 이유
개발 언어와 DB연결이 가능해야 하기 때문

5. 구축 비용
5-1. 라이선스 정책 비용
- DBMS 사용 비용을 의미한다.
ORACLE : 사용,비용이 크다
MySQL : 무료 가능
Redis : 오픈 소스
5-2. 유지 및 관리 비용
- 운영 중 지속적으로 발생하는 비용
관리자 인건비
서버 운영비
백업 비용

- 시스템 전체 운영 기간동안 발생하는 총 비용

서버비용 : 장비 구매
