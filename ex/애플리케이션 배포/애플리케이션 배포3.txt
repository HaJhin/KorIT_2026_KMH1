애플리케이션 배포 환경 구성
1. 애플리케이션 배포 환경 구성
1-1. 소스코드 빌드 과정의 이해
- 컴파일 언어(기계어로 변환되어 실행 C,C++)
- 바이트코드 언어(바이트코드로 변해서 JRE가 실행 JAVA, C#)
- 인터프리터(한줄씩 번역 JS, Python)

1-2. 애플리케이션 배포 환경
- 웹 서버(html, 이미지와 같은 정적 리소스 처리)
- 웹 애플리케이션 서버(동적인 처리 백엔드 처리)

애플리케이션 배포 환경 구성하기
1. 프로젝트 배포 관리 요건을 분석하고 배포환경 구성방안을 계획한다
- 애플리케이션의 기술적인 특성을 확인하고 배포 방식을 정의한다
ㄴ 개발 언어의 확인
ㄴ 프로젝트에 적용되어 있는 개발 도구, 개발 환경을 확인
ㄴ 애플리케이션의 유형을 확인한다.
ㄴ 배포 대상 리소스의 유형 확인(jar,war,ear)
ㄴ 배포 대상 리소스 유형을 확인(이미지,html,서버 프로그램...)
ㄴ 배포시 연계하여 처리하고자 하는 프로젝트 요건 확인

- 개발하려는 애플리케이션의 인프라 환경을 확인하고 배포 대상 서버를 확인
ㄴ 개발하려는 애플리케이션의 서버 구성 환경을 확인한다.
ㄴ 리소스 유형별 배포 대상 서버를 확인한다
ㄴ 분산 배포 대상을 확인한다
ㄴ 통합 빌드 배포 구성도를 작성한다

2. 애플리케이션 배포를 위한 도구와 시스템 선정
- 소스 형상관리 도구를 선정
- 빌드 도구 선정
- 테스트 도구 선정
- 검토 대상 코드 인스펙션 점검 도구를 파악
- 애플리케이션 개발에 적합한 코드 인스펙션 점검 도구 선정

2. 애플리케이션 배포 환경 설정
2-1. 애플리케이션 배포 단위
- jar(Java Archive)
ㄴ Java 라이브러리, 리소스, 설정파일들을 포장한다.
- war(Web Archive)
ㄴ 웹 컨테이너에 배포, Servlet, jar파일, WEB-INF 안에 있는 web.xml 파일로 구성

web.xml : 웹 애플리케이션이 실행될때 가장 먼저 읽히는 파일

- ear(Enterprise Archive)
ㄴ jar와 war를 묶어서 하나의 완성된 웹 애플리케이션 서비스를 제공

2-2. 형상관리 시스템
- 형상관리의 범위
ㄴ 신규 프로젝트 및 보완 개발, 업무 시스템의 운영/유지보수, 전산 설비 및 시스템 소프트웨어 등과
관련된 작업, 사용자 파일 관리
- 형상관리 시스템에서 사용하는 용어
ㄴ 형상관리 : 소프트웨어 전체 생명 주기를 지속적으로 관리하는 것
ㄴ 형상항목 : 관리의 대상이 되는 항목, 소스파일, 문서, 기타 사항
ㄴ 기준선 : 공식적으로 검토되고 협의되어 향후 기준이 되는 형상 항목의 집합체
ㄴ 마이그레이션 : 개발 완료된 시스템이 운영단계로 전환될 때 관련 소스 파일을 저장공간으로 이관시키는 작업
ㄴ 리포지터리 : 관리 대상을 일괄 전송하여 압축, 암호화한 후에 저장, 관리하는 저장공간을 의미
ㄴ 워크플로 : 형상관리 활동을 수행하기 위해 미리 정해진 절차
ㄴ 반출(check Out) : 형상 항목을 수정하기 위해 리포지터리로부터 전송받는 것
ㄴ 반입(Check In) : 반출된 형상 항목을 변경 후 다시 형상 리포지터리로 전송하는 것

애플리케이션 배포 환경 설정하기
1. 애플리케이션 배포를 위한 도구와 시스템 설치
- 빌드, 배포 환경을 정의
ㄴ 프로젝트의 빌드 요건, 인프라 환경, 선정된 빌드, 배포 도구를 바탕으로 환경 구성을 정의
- 선정된 빌드,배포 도구를 설치한다(서버단)
ㄴ 개발자의 개발 환경에 배포되어야 하는 Agent, 플러그인이 있는 경우 해당 도구를 배포하고 모든 개발자가 설치하도록 한다.

2. 애플리케이션 개발 기간 중 적용하 배포 절차 및 역할을 정의한다
- 애플리케이션 개발 기간 중 사용할 배포 유형 및 기준을 정의
ㄴ 긴급 적용 - 장애나 오류 발생 시(개발자가 직접 즉시 배포 또는 관리자,PL의 최소한의 확인만 수행)
ㄴ 일반 적용 - 개발, 수정된 프로그램에 대한 일반적인 적용(관리자,PL 확인 및 배포관리자 확인, 테스트 수행 결과물 확인)
ㄴ 통합 빌드 - 주기적으로 전체 개발 내역을 확인, 점검하는 경우(배포 관리자가 애플리케이션 전체 소스를 일괄하여
빌드,배포 후 점검 보고서 추출)

- 애플리케이션 개발 기간 중 상용할 애플리케이션 배포 절차를 정의
- 애플리케이션 개발 기간 중 배포를 위한 관계자를 역할과 책임 정의
ㄴ 배포 관리자 : 빌드,배포 환경 구성 및 운영, 빌드 스크립트 작성 및 테스트
빌드,배포 내역 오류 확인, 배포 요청 내역 검토 및 오류 확인, 주기적 통합 빌드 및 배포 수행
ㄴ 프로젝트 PM, PL : 빌드, 배포 보고서 확인, 개발 진척도 관리, 테스트 케이스 작성 내역 검토
ㄴ 개발자 : 테스트 케이스 작성 및 관리, 갭려 모듈 수시 빌드 및 배포, 빌드, 배포 내역 정상 여부 확인

애플리케이션 소스 확인
1. 코드 인스펙션
- 정적 테스트의 가장 일반적인 유형으로, 사전에 정의된 코드 작성 규칙 기반으로 소스 코드를 점검하여 작성 규칙에 위반되는
소스코드를 추출하는 분석 도구
- 코드 인스펙션 Rul 유형
ㄴ 성능 개선 : 성능에 영향을 미칠 수 있는 코드 점검
ㄴ 코드 작성 규칙
ㄴ 에러 발생 가능성
- 코드 작성 Rule 심각도 구분
ㄴ 필수 Blocker : 에러 발생 가능성이 높거나 일반적으로 수정되어야 하는 심각한 위반 사항
ㄴ 권고 상 Critical : 에러 발생 가능성이 높거나 일반적으로 수정되어야 하는 심각한 위반 사항
ㄴ 권고 중, Major : 에러 발생 가능성이 있거나 수정을 권고하는 중요 위반 사항
ㄴ 권고 하, Minor : 소스코드의 가독성, 유지보수성 향상을 위해 수정을 권고하는 위반사항
ㄴ 정보 Info : 정보성으로 제공되는 위반 사항으로 개발자가 참고하여 적용할 수 있다.

- 정규 표현식 : 특정한 규칙을 가진 문자열의 집합을 표현하는 범용적 방식

애플리케이션 소스 확인하기
1. 코드 인스펙션 점검 Rule을 확인한다
2. 애플리케이션에 정의된 개발 표준을 바탕으로 추가,보완할 점검 Rule이 없는지 확인한다.
3. 추가 보완이 필요한 점검 Rule을 추가 수정하여 반영한다
4. 코드 인스펙션 점검 수행을 위한 수행 절차를 정의한다.
- 코드 인스펙션 점검 방식을 정의한다
- 코드 인스펙션 점검 주기를 정의한다
- 코드 인스펙션 점검 수행 절차를 정의한다.

변경 대상이 되는 애플리케이션 소스를 형상관리 서버로부터 반출한다.
1. 변경이 요구되는 대상 응용 프로그램, 개편 일정 등을 종합적으로 정리한 개편 계획서를 작성하여 관리자의 승인을 받는다
2. 변경이 요구되는 자원을 반출하기 위한 반출 의뢰서를 작성하여 관리자의 승인을 받은 후 반출한다.
