OSI 7 계층
컴퓨터끼리 통신할 때 어떤 일을 단계별로 나눠서 처리하는 구조

데이터를 한번에 막 보내는게 아니라 7단계로 나눠서 보내고 받도록 정리한 개념

OSI 7계층이 필요한 이유
예전에는 컴퓨터 제조사나 시스템마다 통신 방식이 제각각이었다.
서로 통신이 어려웠음

국제표준화기구(ISO)가 통신과정을 단계별로 나눠서 표준처럼 이해하자

1. 통신 과정을 쉽게 이해할 수 있다.
- 복잡한 통신을 한 번에 보면 어렵다
- 기능을 층별로 나눠서 본다.

2. 문제가 생겼을 때 어디서 고장 났는지 찾기 위해서
- 예를 들어 인터넷이 안될때
- 케이블 문제인지
- IP 문제인지
- 프로그램 문제인지
구별해서 볼 수 있게 된다

3. 장비와 기술의 역할을 정리하기 위해
- 허브, 스위치, 라우터, IP, TCP, 브라우저, 웹서버와 같은 것들이 어느 계층에서
동작하는지 구분할 수 있다.

각 계층

[1계층 : 물리 계층(Physical Layer)]
- 데이터를 실제로 보내는 계층이다.
- 전기 신호,빛,무선 신호처럼 눈에 보이지 않는 실제 신호로 데이터를 전달한다.
- 랜선, 광케이블, 허브, 리피터, 무선 전파, 커넥터 등등

허브(여러 컴퓨터를 연결하는 장치)
리피터 : 약해진 네트워크 신호를 다시 강하게 만들어주는 장치

이 계층의 특징
- 데이터의 의미는 모르고 일단 신호를 보냄
- 문자인지 이미지인지 식별 불가
- 오직 비트(0,1)수준으로 처리
- Like 택배를 실은 트럭

[2계층 : 데이터 링크 계층]
- 같은 네트워크 안에서 데이터가 제대로 가도록 처리하는 계층
- MAC 주소를 사용한다.
ㄴ MAC 주소란 네트워크 카드에 부여된 고유한 물리 주소이다.
- 장비 자체의 주소라고 보면 된다.
내 PC의 랜카드 주소
스위치가 장비를 구분할 때 사용하는 주소

이 계층의 주요 역할
- 프레임 단위로 데이터 구성
- 같은 Lan 안에서 목적지 찾기
- 오류 확인
- MAC 주소 기반 전달

대표 장비
스위치 : 여러 장치를 연결하면서 필요한 장치에게만 데이터를 전달하는 네트워크 장비
ㄴ 목적지 장치에만 전달하고 충돌 거의 없음, 속도도 빠름

허브는 모든 장치에게 데이터를 전송(비효율적임)
충돌 발생 많고 보안이 취약하다

택배상자에 '이 건물(스위치)안에서 누구에게 전달할지'를 적는것

[3계층 : 네트워크 계층(Network Layer)]
- 서로 다른 네트워크를 넘어 목적지까지 가는 길을 찾는 계층
여기서 가장 중요한 것이 IP 주소이다.

IP 주소
인터넷이나 네트워크에서 장치를 식별하기 위한 논리적 주소이다.

이 계층의 핵심 역할
- 목적지 IP 주소 확인
- 어느 경로로 갈지 결정
- 여러 네트워크를 거쳐 전달

대표 장비
라우터(Router)
- 서로 다른 네트워크를 연결하고 데이터를 목적지까지 가장 적절한 경로로 보내는 장치

2계층이 "같은 건물 안에서 누구에게 줄까" 라면, 
3계층은 "서울에서 부산까지 어떤 길로 갈까"를 결정하는 단계

LAN(Local Area Network)
좁은 범위의 네트워크
- 집
- 학교
- 회사 내부

MAN(Metroplitan Area Network)
도시단위 네트워크
- 하나의 도시 전체 연결

WAN(Wide Area Network)
넓은 범위의 네트워크
- 국가
- 전 세계

[4계층 : 전송 계층(Transport Layer)]
- 데이터를 정확하고 안정적으로 전달할지, 아니면 빠르게 보낼지 결정하는 계층
TCP and UDP

이 계층의 핵심 역할
- 데이터 분할
- 순서 맞추기
- 누락 확인
- 재전송
- 흐름 제어
- 포트번호 사용

포트
한 컴퓨터 안에서도 여러 프로그램이 동시에 통신한다.
그래서 어느 프로그램으로 보내야 하는지 구분하는 번호

80번 포트 : HTTP
443번 포트 : HTTPS

[5계층 : 세션 계층(Session Layer)]
- 통신 연결을 시작하고, 유지하고, 끝내는 역할을 한다.

세션
통신 흐름의 연결 상태

역할
- 연결 시작
- 연결 유지
- 연결 종료
- 대화 동기화

세션은 마치 전화통화 같은 것
전화를 건다 - 세션 시작
대화를 한다 - 세션 유지
전화를 끊는다 - 세션을 끊는다

왜 필요한가
- 두 프로그램이 데이터를 주고 받을 때 아예 연결 상태를 관리하지 않으면 중간에 끊겼는지, 계속 대화중인지
파악하기 어렵다

[6계층 : 표현 계층(Presentation Layer)]
- 데이터를 서로 이해할 수 있는 형태로 바꾸는 계층

보내는 쪽과 받는 쪽의 데이터 표현방식이 다를 수 있기 때문에 그 차이를 맞춰주는 역할을 함

주요 역할
- 데이터 형식 변환
- 문자 인코딩 처리
- 암호화/복호화
- 압축/해제

[7계층 : 응용 계층(Application Layer)]
사용자가 실제로 접하는 네트워크 서비스 계층

우리가 프로그램을 통해 사용하는 웹, 이메일, 파일 전송과 같은 서비스가 이 계층과 가깝다.

보낼때
ex) 사용자가 웹 브라우저에서 사이트 접속 요청을 한다
1. 응용계층
- 브라우저가 HTTP 요청을 만든다.
2. 표현계층
- 필요한 형식 변환, 암호화 등을 처리한다.
3. 세션 계층
- 통신 연결 흐름을 관리한다.
4. 전송 계층
- TCP를 사용해 데이터를 잘게 나누고 포트 번호를 붙인다.
5. 네트워크 계층
- IP 주소를 붙여 목적지를 정한다.
6. 데이터링크 계층
- MAC 주소를 붙여 같은 구간에 전달할 수 있게 한다.
7. 물리 계층
- 전기 신호나 무선 신호로 실제 전송한다.

받는 쪽
1. 물리계층에서 신호를 받는다.
2. 데이터링크 계층에서 프레임을 확인한다.
3. 네트워크 계층에서 IP를 확인한다.
4. 전송계층에서 TCP/UDP 포트를 확인한다.
5. 세션 계층에서 연결 상태를 본다.
6. 표현 계층에서 해석 가능한 형식으로 바꾼다.
7. 응용 계층에서 최종적으로 프로그램이 데이터를 사용한다.

프로토콜(protocol)
- 컴퓨터끼리 대화(통신)할때 지켜야 하는 규칙

핵심 구성요소
- 구문(데이터의 형식)
- 의미(보내진 데이터가 무엇을 의미하는지, 어떤 동작을 해야하는지)
ㄴ 요청 메서드 GET,POST,PUT,DELETE
ㄴ 응답 코드 2XX,3XX,4XX,5XX
- 타이밍(언제보내고,순서,속도)

대표적인 프로토콜의 종류
HTTP,HTTPS -> 브라우저가 서버에 페이지를 요청할 때
FTP -> 파일 전송 (개발 : 윈도우, 운영 : 리눅스)
TCP -> 데이터를 정확하고 안정적으로 보낼때
UDP -> 빠르게 보내는 것에 집중하는 프로토콜

OSI 7계층 (정처기 시험때 잘나오는 소재) !+!
- 컴퓨터끼리 통신할 때 7단계로 나눠서 처리하는 구조
1계층 : 물리 계층
- 데이터를 실제로 보내는 계층
- 데이터의 상태가 bit이다.
- 전기, 빛, 전파와 같은 순수 신호 상태
장비 : 허브, 리피터

2계층 : 데이터 링크 계층
- 같은 네트워크 안에서 데이터가 제대로 가도록 처리하는 계층
데이터 형태 : Frame
ㄴ Packet에 MAC 주소와 오류 검출 정보가 붙은 것
- MAC 주소 : 인터넷을 연결할 수 있는 기기에 할당되어있는 고유 ID
- 스위치 : 필요한 곳에만 데이터를 전송하는 장비
ㄴ 스위치가 어느 장비로 데이터를 보낼지 판단할때 사용하는 것이 MAC 주소이다.
- 브리지

3계층 : 네트워크 계층
- 서로 다른 네트워크를 넘어 목적지까지 가는 길을 찾는 계층
- ip 주소를 사용
데이터 상태 : Packet
ㄴ Segment에 출발지와 목적지의 IP주소가 붙은 상태
라우터 : 서로 다른 네트워크를 연결해주는 장비
L3 스위치 : 스위치에 라우터를 합친 장비

4계층 : 전송 계층
- 데이터를 정확하고 안정적으로 전달할지, 빠르게 전달할지 결정하는 계층
데이터 상태 : Segment(상위 계층에서 내려온 Data에 프로세스 간 통신을 위한 정보가 붙은 상태)
L4 스위치 : IP + 포트번호를 기준으로 트래픽을 분해하는 장비
로드 밸런서 : 서버 여러 대에 트래픽을 균등하게 나눠주는 장비
일부 방화벽

5계층 : 세션 계층
- 통신의 시작, 유지, 종료를 관리하는 계층
데이터의 상태 : Data

6계층 : 표현 계층
- 데이터의 표현 방식을 맞춰주는 계층
- 데이터를 보기 좋게 변환한다
데이터 상태 : Data

7계층 : 응용 계층
- 사용자가 직접 만나는 계층
- 웹 브라우저, 메일 프로그램, 파일 전송 프로그램 등이 관련이 있다.
데이터 상태
Data : 여기서는 아직 사람이 이해할 수 있는 실제 내용

데이터 전송 흐름
7 -> 6 -> 5 -> 4 -> 3 -> 2 -> 1
1. 응용 -> HTTP 요청을 생성
2. 표현 -> 암호화/변환
3. 세션 -> 연결 생성
4. 전송 -> TCP + 포트
5. 네트워크 -> IP 주소
6. 데이터링크 -> MAC 주소
7. 물리 -> 신호로 전송

데이터 수신 흐름
전송 흐름의 역순
1. 신호 수신
2. 프레임 확인
3. IP 확인
4. 포트 확인
5. 세션 확인
6. 데이터 해석
7. 프로그램 전달

통신은 요청 <-> 응답
요청(request)을 하는 쪽을 클라이언트(Client)라고 한다.
응답(response)을 하는 쪽을 서버(Server)라고 한다.

http는 한 번 연결을 하고 나면 기억을 하지 않는다.
1. 클라이언트가 요청을 보냄
2. 서버가 응답을 보냄
3. 연결 종료

서버 입장에서는 "이 사용자가 방금 전에 뭘 했는지 모름"
로그인 요청 -> 성공

로그인이나 장바구니 등이 유지가 안됨

상대를 구분하기 위해 별도의 기술을 활용

1. 쿠키
브라우저에 저장되는 데이터
서버 -> 쿠키를 발급
브라우저는 -> 요청할 때마다 쿠키를 같이 자동으로 전송

2. 세션
서버가 사용자 상태를 기억
java에 Session 클래스가 있다.
세션 객체를 만들어서 사용자 상태를 저장한다.

3. 토큰(jwt)
- 요즘 가장 많이 사용하는 MZ 방식
로그인 성공 -> 토큰 발급
클라이언트가 저장
요청 시 토큰을 같이 보냄

MSA(Microservice Architecture)
- 분산 시스템을 구성하기 위해 하나의 큰 어플리케이션을 여러 개의 작은 서비스로 나눠서 개발하고
운영하는 구조
- 각각의 서비스는 독립적으로 실행된다.
- 서비스끼리는 네트워크로 통신(HTTP 등)
- 배포도 각각 따로 가능함

분산 시스템 SW

시스템
여러 요소가 모여 하나의 기능을 수행하는 구조

분산
한 곳에 몰아두지 않고 여러 곳에 나누는 것

SW
그 구조가 실제로 동작하도록 만드는 소프트웨어

여러 컴퓨터에 기능을 나누어 배치하고 이들이 서로 통신하면서
하나의 시스템처럼 동작하게 하는 소프트웨어

왜 분산 시스템 SW가 필요할까
- 한 대의 서버로도 프로그램은 만들 수 있다.
사용자가 많아지고, 기능이 많아지고, 장애에 강해야 하면 한 대만으로는 한계가 생김

쇼핑몰에 사용자가 갑자기 10만명이 몰리면, 한 서버가 감당하기 어렵다.

서버1 : 로그인
서버2 : 상품목록
서버3 : 결제
서버4 : 리뷰

한 대의 서버가 있으면 그 서버가 죽는 순간 서비스 전체가 멈춘다
여러 서버로 나누면 일부 서버가 고장나도 서비스가 완전히 멈추지 않도록 설계할 수 있다.

분산 시스템 SW 구성 요소

1. 어플리케이션 서버
- 실제 비즈니스 로직을 처리하는 서버

데이터(Data)의 개념

데이터베이스의 특징
실시간 접근성
- 요청받은 데이터는 실시간으로 처리되고 결과를 반환해야 한다.
계속적 변화
- 저장된 데이터는 입력, 수정, 삭제에 의해 지속적으로 변화한다.
동시 공용
- 서로 다른 목적의 소프트웨어 및 사용자에 의해 동시 공용 가능
내용에 의한 참조
- 데이터 참조는 데이터의 주소가 아닌 저장된 값에 의해 처리된다.

데이터베이스 관리 시스템(DBMS: Database Managemnet System)
- 다수의 응용 소프트웨어 및 사용자가 데이터베이스에 접근하여 저장되어 있는 데이터베이스를 필요에 따라
사용할 수 있도록 관리해주는 시스템

데이터베이스 관리 시스템의 기능
동시성 제어
- 다수 트랜잭션의 동시 처리로부터 데이터 무결성 확보를 위한 제어 수행
ㄴ 여러 사용자가 같은 데이터에 동시에 접근할 때
A가 같은 계좌에서 5만원 출금
B가 같은 계좌에서 3만원 출금
회복관리
- 시스템 오류 및 장애로 인한 데이터 손실 및 결함의 대응
성능
- 데이터 처리 속도 확보를 위한 실행 계획의 최적화
보안 관리
- 비인가 사용의 접근 제어 및 중요한 정보의 암호화

데이터베이스 관리 시스템의 유형
계층형
- 트리구조로 데이터 저장(부모-자식 관계가 형성)

- 데이터 접근속도 빠름, 구조는 단순함
- 구조 변경이 어려움, 유연성 부족, 관계가 복잡해지면 관리가 어려움

- 데이터 노드와 관계를 링크로 연결
- 복잡한 관계표현 가능, 데이터 무결성 높음
- 구조가 복잡함, 설계, 유지보수가 어려움

- 대규모 데이터 처리 시 성능 저하 가능

※ ACID
A(Atomicity 원자성) -> 트랙잭션이 여러개일때 전부 성공하거나 전부 실패해야 한다.
C(Consistency 일관성) -> 트랜잭션 전후에 데이터 규칙이 유지되어야 한다.
I(Isolation 격리성) -> 여러 트랜잭션이 서로 간섭하지 않아야 한다.
D(Durability 지속성) -> 성공한 작업은 절대 사라지면 안된다.

트랜잭션
데이터베이스 관리시스템에서 저장된 데이터의 상태를 바꾸기 위해 수행하는 작업의 논리적 단위
ㄴ 논리적 단위의 의미는 여러 개의 작업을 하나로 묶어서 '전부 성공시키거나' '하나라도 실패하면 전부 실패시키는 것'을 의미함
