JRE System Library

오버로딩(overloading)
- 같은 이름으로 서로 다른 개수,타입의 매개변수를 각각 처리하는 방법

- 반환형은 달라도 상관없음
- 메서드(or 생성자)명은 같아야 함
- 매개변수의 개수가 다르거나, 타입이 다르거나, 순서가 달라야함.

접근제한자 (Access Modifier)
public : 프로젝트 내에서는 어디서든지 사용 가능
default : 같은 패키지 내의 다른 클래스 어디서든지 사용가능
private : 현재 클래스에서만 사용 가능
protected : 같은 패키지와, 상속한 자식 클래스가 사용 가능

Class 클래스
왜 사용하는가?
1. 객체를 동적으로 생성 가능
자바코드 -> 컴파일 -> 바이트코드 -> 실행
일반적인 객체의 생성
Car car = new Car(); -> 컴파일 시점 클래스 결정
Class clazz = Class.forName("클래스명"); -> 실행 중에 클래스 결정 가능

용도
플러그인 : 기본 프로그램에 외부 기능을 끼워넣는것

2. 보통의 프로그램은 미리 정해진 클래스만 사용한다.
하지만 어떤 경우에는 실행하기 전까지 어떤 클래스를 쓸지 모르는 경우가
있다.
- 프로그램에 새로운 기능을 나중에 추가하고 싶다.
- 설정 파일에 따라 다른 객체를 만들고 싶다.
- 외부 개발자가 만든 기능을 꽂아 넣듯이 연결하고 싶다.

3. 프레임 워크에서 자동 처리
- 나중에 우리가 직접 안써도 스프링부트 내부에서 사용 중

- 사용자가 로그인을 시도

- 에러가 발생했을 때

어노테이션
코드에 붙이는 표식같은 것
클래스,필드,메서드 등에 붙여서 코드에 대한 추가정보를 전달할때 사용한다.
코드 자체의 실행문은 아니지만 이 코드가 어떤 의미인지, 컴파일러가 무엇을 확인해야 하는지, 프레임워크가 어떻게 처리해야하는지와 같은 정보를 알려주는 역할을 한다.

어노테이션을 왜 사용할까?

1. 실수를 줄여준다.
2. 코드의 의미를 더 분명하게 보여준다.
[자바의 기본 제공 어노테이션]
@Override
@Deprecated : 없데이트니까 쓰지 마셈
@SupressWarning : 경고 무시 
[메타 어노테이션]
@Retention : 언제까지 정보를 유지할건지
@Target : 어디에 적용할건지

커스텀 어노테이션
public @interface 어노테이션명 {}

제네릭
타입을 미리 고정하지 않고 나중에 정할 수 있게 만드는 문법
어떤 타입이든 담을 수 있는 틀을 만든 뒤 사용할 때 타입을 정한다.
제네릭이 없으면 타입 안정성이 떨어지며, 형변환 코드가 많아지고 실수의 발견이 늦어진다.
