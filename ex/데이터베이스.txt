미들 웨어
프로그램과 운영체제 또는 여러 시스템 사이에서 서로 연결하고 도와주는 프로그램

미들웨어는 사용자가 직접 눈으로 보는 프로그램은 아니지만, 시스템이 정상적으로 동작하기 위해 뒤에서 중요한 역할을 한다.

미들웨어를 사용하는 이유
1. 서로 다른 시스템을 연결하기 위해
- 시스템마다 언어, 데이터 형식, 통신 방식이 다를 수 있다.
이러한 시스템들을 연결해주는 역할을 한다.

2. 개발자가 공통기능을 직접 만들지 않아도 된다.
로그인 세션 관리, 보안 처리, 데이터 변환, 메시지 전송
이런 기능을 개발자가 전부 직접 만들면 시간도 오래 걸리고 실수도 많아진다.
미들웨어는 공통 기능을 제공해준다.

3. 시스템을 안정적으로 운영하기 위해
짧은 시간에 요청이 몰리는 것들을 처리
- 요청을 여러 서버로 나눠서 보냄
- 동시에 들어온 요청을 순서 있게 처리

스키마를 사용하는 이유
1. 데이터 구조를 정리하기 위해
- 구조를 정해서 일관성을 유지

2. 데이터 관리 단위로 사용하기 위해
- 프로젝트 별로 DB를 나눌 수 있다.
- 예 : 쇼핑몰 / 게시판 / 회원관리

3. 접근 권한 관리
- 특정 스키마만 접근하도록 설정 가능

데이터베이스는 좀 더 깊은 개념으로 3가지로 나눈다
1. 외부 스키마
- 사용자 입장에서 보는 구조

2. 개념 스키마
- 전체 데이터 구조

3. 내부 스키마
- 실제 저장 방식
- 디스크에 어떻게 저장되는지

Data : 가공되지 않은 단순간 사실이나 값
DB : 데이터를 체계적으로 저장해놓은 공간
DBMS : 데이터베이스를 관리하는 프로그램(소프트웨어)

DBMS의 종류
1. 계층형 데이터베이스
- 트리 구조로 데이터를 저장하는 방식
- 1: N 관계만 가능하다
- 구조가 단순하지만 변경이 어렵다.

2. 네트워크형 데이터베이스
- 데이터를 그래프 형식으로 연결하는 방식
- N : N 관계가 가능함
- 계층형보다는 유연하다.
- 구조가 복잡함
- 여러 개의 연결을 허용하는 DB

3. 관계형 데이터베이스
- 테이블 형태로 데이터를 저장하는 방식
- 가장 많이 사용됨
- SQL을 사용
- 데이터의 무결성을 보장한다.

4. 객체지향형 데이터베이스
- 객체(Object) 형태로 데이터를 저장
- Java,C++ 객체 그대로 저장 가능
- 복잡한 데이터 처리에 유리
- 사용 빈도는 낮음

제약조건
- 문제가 되는 데이터를 테이블에 추가할 수 없도록 제한하는 조건
- 테이블을 만들면서 설정할 수 있고, 추후에 생성하거나 변경할수도 있다.

PRIMARY KEY(기본 키)

NOT NULL
- 해당 속성에는 반드시 값이 들어가야 한다.

UNIQUE
- 속성에 들어가는 값은 유일해야 한다.

FOREIGN KEY(외래키)
- 다른 테이블의 기본키 값을 참조하는 제약조건

CHECK
- 속성에 들어갈 수 있는 데이터의 조건을 설정하는 제약조건

DEFAULT
- 값을 입력하지 않았을 때 자동으로 들어가는 기본값을 설정

데이터베이스 객체의 수정
ALTER

컬럼의 추가
ALTER TABLE 테이블명 ADD COLUMN 컬럼명 자료형;

컬럼의 삭제
ALTER TABLE 테이블명 DROP COLUMN 컬럼명;

컬럼명 변경
ALTER TABLE 테이블명 RENAME COLUMN 컬럼명 TO 변경할 이름;

자료형의 변경
ALTER TABLE 테이블형 MODIFY COLUMN 컬럼명 자료형

제약조건 추가
ALTER TABLE 테이블명 ADD 제약조건 종류(컬럼);

제약조건 삭제
ALTER TABLE 테이블명 DROP 제약조건 종류(컬럼);
- 기본키의 경우는 이름없이 삭제 가능
- 나머지 제약조건은 이름을 명시해줘야 함

- NOT NULL과 DEFAULT는 MODIFY를 사용한다.

무결성
- 데이터베이스에 저장된 데이터가 현실세계의 실제값과 일치하는 정확성을 의미한다.

1. 개체 무결성
- PK로 설정된 컬럼은 반드시 고유한 값을 가져야 하고, NULL이 될 수 없다.

2. 참조 무결성
- 외래키(FK)값은 NULL이거나, 반드시 참조하는 테이블의 PK에 들어있는 값과 일치해야한다.
- 존재하지 않는 값은 외래키로 저장할 수 없다.

3. 도메인 무결성
- 특정 속성의 값이 미리 정의된 유효한 값 범위 안에 있어야한다.

4. 사용자 정의 무결성
- 사용자가 논리적으로 필요한 규칙을 직접 정의하는 것
- 나이는 음수가 들어올 수 없다. 가입일은 오늘 이후일 수 없다.

정규화
ERD 내에서 중복 요소를 찾아 제거해나가는 과정
1차~5차 정규화가 존재한다.

1 정규형
- 한칸에는 하나의 값만 들어가야 한다.

2 정규형
- 1차 정규화를 만족하면서 기본키의 일부에만 의존하는 속성을 분리한다.

3 정규형
- 2차 정규화를 만족하면서 기본키가 아닌 다른 컬럼이 다른 일반 컬럼을 결정하면 분리한다.

복합키
- 여러개의 속성을 묶어서 하나의 기본키로 사용하는 것
- 여러 컬럼의 값을 조합해서 겹치는 값이 없으면 된다.

이행함수 종속
A -> B, B -> C, A -> C가 성립되는 관계
중간 속성을 통해 간접적으로 결정되는 관계

정규화를 통해서 테이블을 너무 많이 쪼개게 되면 조회를 할때 성능이 떨어질 수도 있어서,
역정규화를 할 때도 있다.

데이터 모델링
- 현실세계의 업무 내용을 데이터베이스에 저장할 수 있도록 데이터 구조로 설계하는 과정

모델링이 필요한 이유
1. 데이터 중복이 발생할 수 있음
2. 갱신 이상 -> 같은 정보가 여러개 저장되어 있을 떄 전부 수정하지 않아서 데이터 불일치가 일어나는 현상
3. 삭제 이상 -> 필요없는 데이터를 지우려다 필요한 데이터까지 삭제하는 경우
4. 삽입 이상 -> 필요한 데이터를 추가하려다 필요없는 데이터까지 추가하는 경우

데이터 모델링 과정
1. 요구사항 분석
- 업무에서 어떤 데이터를 관리해야 하는지 파악하는 단계
- 주요 명사를 찾아서 -> 엔티티로 만든다.

2 개념적 모델링
- 업무 내용을 큰 그림으로 표현하는 단계
- 주로 ERD를 사용한다.

주요 구성 요소
엔티티(Entity) : 관리해야 할 대상
속성(Attribute) : 엔티티가 가진 정보
관계(Relationship) : 엔티티 간 연결
식별자(Identifier) : 데이터를 구분하는 값

논리 모델링
- 개념적 모델을 실제 테이블 구조에 가깝게 바꾸는 단계
- ERD를 가지고 테이블을 설계
- 테이블의 이름이나 속성의 이름을 정하는 단계
- 제약조건(PK,FK등) 정규화

- 관계를 문장으로 처리
학생은 수강신청을 한다
수업은 수강신청을 받는다.
강사는 수업을 담당한다.

관계 차수 정하기
1:1,1:N,M:N 중 어떤 관계인지 정한다.

정규화
실무에서는 보통 3차까지 다룸 -> 더 하면 오히려 속도가 느려짐
1NF -> 속성 하나에는 하나의 값만 들어가야 한다.
2NF -> 복합키에서 일부 컬럼에만 의존하는 컬럼을 제거
3NF -> 일반 컬럼이 다른 일반 컬럼을 결정하면 안됨 (이행함수 종속)
BCNF(Boyce-Codd Normal Form)
- 제 3정규형을 좀 더 엄격하게 적용한 정규형
- 모든 함수적 종속에서 결정자는 반드시 후보키여야 한다.
※ 결정자 : 관계형 데이터베이스에서 다른 속성의 값을 유일하게 결정짓는 속성들의 집합을 의미한다.
※ 후보키 : PK가 될 수 있는 속성
제3정규형을 지켜도 이상 현상이 남아있을 수 있다.

4NF -> 다중값 종속 제거(한 엔티티가 서로 독립적인 여러 값 집합을 가지면 분리)
5NF -> 조인으로 복원 가능한 경우 분리
- 어떤 테이블이 여러 개의 테이블로 분해되었을 때 JOIN을 하면 항상 원래 테이블이 나올 수 있는지

DML(Data Manipulation Language) : 데이터 조작어
- 데이터에 대해서 조회,수정,추가,삭제하는 명령어

SELECT ~ FROM 테이블;
모든 내용 조회 : SELECT * FROM 테이블;

특정 조건에 맞는 데이터만 조회하고 싶다
where 조건
where절은 from절 뒤에 작성을 한다.
db에서 =은 equal이라는 뜻
<>,!= 같지 않다

NULL값이 들어있는 데이터를 조회

날짜 비교

LIKE
- 문자열 안에서 특정 글자나 패턴을 찾을 때 사용하는 조건문
SELECT 컬럼명 FROM 테이블명 WHERE 컬럼명 LIKE '패턴'

SELECT * FROM FILM WHERE TITLE = 'LOVE'
- 이 SQL은 제목이 정확히 LOVE인 영화만 찾는다.
LIKE는 포함 여부, 시작이나 끝 문자, 특정 문자 패턴을 찾을 수가 있다.

% : 글자 수와 상관없이 아무 문자나 여러 개 올 수 있다는 뜻

'A%' : A로 시작하는 데이터
'%A' : A로 끝나는 데이터
'%A%' : A를 포함하고 있는 데이터
'A%B' : A로 시작하고 B로 끝나는 값

_ : 문자 1개를 의미한다.

'A_' : A로 시작하고 전체 길이가 2인 값
'A__' : A로 시작하고 전체 길이가 3인 값
'_A' : A로 끝나는 전체 길이가 2인 값
'_A_' : 전체 길이가 3이고 A가 가운데 있는 값

DCL(Data Control Language) : 데이터 제어어
GRANT : 권한을 부여
REVOKE : 권한을 회수
- 데이터베이스에서 사용자 권한을 관리하는 SQL이다.
DCL이 필요한 이유
- 모든 사용자에게 권한을 주면 위험하기 때문

MySQL에서는 사용자를 다음과 같이 구분한다.
'사용자명'@'접속자위치'
'teacher'@'localhost'

사용자 생성하는 법
create user '사용자명'@'접속자위치'
identified by '비밀번호';

-- GRANT
-- 사용자에게 권한을 주는 명령어
-- GRANT 권한 ON 데이터베이스명.테이블명 TO '사용자명'@'접속위치';

함수적 종속성
- 어떤 속성의 값이 정해지면, 다른 속성의 값도 자동으로 결정되는 관계

완전함수 종속
- 기본기 전체에 의해 종속되는 경우

부분함수 종속
기본키의 일부만으로 종속되는 경우

이행함수 종속
A -> B , B -> C 면 A -> C가 되는 관계

학번 -> 학과코드 , 학과코드 -> 학과명일때 학번 -> 학과명
수정이상 발생

이상현상
- 데이터베이스 설계가 잘못되어 데이터를 삽입,수정,삭제할 때 비정상적인 문제가 발생하는 현상

삽입이상
- 데이터를 추가하려고 할때 필요없는 데이터까지 강제로 넣어야하는 문제

수정이상
- 같은 데이터가 여러번 저장되어 일부만 수정하면 데이터의 일관성이 사라지는 문제

삭제이상
- 데이터를 삭제할때 유지해야할 다른 정보까지 삭제되는 문제
