## 실무 시나리오

A 온라인 쇼핑몰은 회원과 주문 데이터를 관리하는 시스템을 운영하고 있다.

현재 개발팀은 주문 조회 성능 저하 문제를 해결하기 위해 물리 데이터 모델을 개선하려고 한다.

다음과 같은 요구사항이 존재한다.

- 회원은 여러 개의 주문을 생성할 수 있다.
- 존재하지 않는 회원의 주문 데이터는 저장되면 안 된다.
- 회원 이메일은 중복되면 안 된다.
- 회원 이름은 반드시 입력해야 한다.
- 특정 회원의 주문 내역 조회가 자주 발생한다.
- 다음 조회가 하루 수천 번 이상 실행된다.

# 문제

위 요구사항을 만족하도록 물리 데이터 모델을 설계하려고 한다.

다음 조건에 맞게 SQL을 작성하시오.

# 조건

- DBMS는 MySQL을 사용한다.
- PK 컬럼명은 테이블명_id 형식을 사용한다.
- 회원 테이블명은 `members` 이다.
- 주문 테이블명은 `orders` 이다.
- 회원 테이블 컬럼은 다음과 같다.

| 컬럼명 | 데이터 타입 |
| --- | --- |
| member_id | INT |
| member_name | VARCHAR(50) |
| email | VARCHAR(100) |
- 주문 테이블 컬럼은 다음과 같다.

| 컬럼명 | 데이터 타입 |
| --- | --- |
| order_id | INT |
| member_id | INT |
| order_date | DATE |
- 회원 테이블에는 PK, UNIQUE, NOT NULL 제약조건을 반드시 적용한다.
- 주문 테이블에는 FK 제약조건을 반드시 적용한다.
- 회원 번호 조회 성능 향상을 위한 단일 인덱스를 생성한다.
- 회원번호 + 주문일 조건 검색 성능 향상을 위한 복합 인덱스를 생성한다.
- FK 이름은 `fk_orders_members` 로 작성한다.
- 단일 인덱스 이름은 `idx_orders_member_id` 로 작성한다.
- 복합 인덱스 이름은 `idx_orders_member_date` 로 작성한다.

# 작성해야 하는 내용

1. `members` 테이블 생성 SQL
CREATE TABLE IF NOT EXISTS members(
	member_id INT PRIMARY KEY,
	member_name VARCHAR(50) NOT NULL,
	email VARCHAR(100) UNIQUE
);

2. `orders` 테이블 생성 SQL
CREATE TABLE IF NOT EXISTS orders(
	order_id INT PRIMARY KEY,
	member_id INT NOT NULL,
	order_date DATE NOT NULL,
	CONSTRAINT fk_orders_members FOREIGN KEY (member_id) REFERENCES members(member_id)
);

3. 단일 인덱스 생성 SQL
CREATE INDEX idx_orders_member_id ON orders(member_id);

4. 복합 인덱스 생성 SQL
CREATE INDEX idx_orders_member_date ON orders(member_id,order_date);

- DBMS는 MySQL 기준으로 작성한다.
- View 이름은 `v_order_summary` 로 작성한다.
- 조회 컬럼은 다음만 포함한다.

컬럼명

---

order_id

---

member_name

---

order_date

- 회원과 주문 데이터를 함께 조회해야 한다.
- SQL은 실제 실행 가능한 형태로 작성한다.

CREATE or REPLACE VIEW v_order_summary AS
SELECT o.order_Id,m.member_name,o.order_date
FROM orders o
JOIN member m ON o.member_id = m.member_id
