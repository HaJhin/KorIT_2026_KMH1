COUNT,SUM,MAX,MIN,AVG

집계 함수(그룹 함수)
- 하나 이상의 행에 대한 값들에 대해 집계(개수,총합,최대,최소,평균값)하여 1개의 값으로 반환
- 일반적으로는 일반 속성과 집계함수를 같이 사용할 수는 없다.
- NULL값은 집계하지 않는다.

- 부서별, 상품별, 카테고리별 등...

from employees group by department_id

그룹을 지을 때 꼭 한가지 속성만 쓸 수 있는 것은 아님

having
- group by로 만든 그룹을 조건으로 필터링을 할 때 사용하는 문법
- where은 -> 전체 행에 대해서 필터링
- having -> 그룹핑을 하고 난 다음 필터링

정렬(order by)
- 조회 결과를 원하는 순서로 정렬할 때 사용하는 문법
- 오름차순(ASC) : 작은거 -> 큰거
- 내림차순(DESC) : 큰거 -> 작은거
select 컬럼명 from 테이블명 order by 정렬기준컬럼 정렬방식;

순위를 정하는 함수 (윈도우 함수)
- ROW_NUMBER() : 무조건 1,2,3,4,처럼 번호를 붙인다.
- RANK() : 공동순위를 인정하고 다음 순위를 건너뛴다.
- DENSE_RANK() : 공동 순위를 인정하지만 다음 순위를 건너뛰지 않는다.
- NTILE(n) : 데이터를 n개의 그룹으로 나눈다.
순위함수() OVER(ORDER BY 정렬기준컬럼 정렬기준)

index
테이블에서 데이터를 더 빠르게 찾기 위해 만드는 검색용 목차
select * from student where name = '박민수';
인덱스가 없으면 MySQL은 데이터를 처음부터 하나씩 확인한다.
이런 방식을 Full Table Scan(전체 테이블 스캔)이라고 한다.

인덱스 생성 기본 문법
CREATE INDEX 인덱스명
ON 테이블명(컬럼명)

CREATE INDEX inx_student_name
ON student(name);

name값을 기준으로 정렬된 별도의 구조를 만든다.
[김철수] -> 데이터 위치
실제 테이블을 이름순으로 바꾸는 것이 아닌, 이름순으로 찾기 좋은 별도의 목차를 만든다.
쿼리를 실행하면 인덱스가 자동으로 사용됨

인덱스 확인법
SHOW INDEX FROM 테이블명;

인덱스 삭제
DROP INDEX 인덱스명 ON 테이블명;

테이블을 만들때 PK를 설정하면 MySQL은 자동으로 인덱스를 생성한다.

UNIQUE 제약조건도 자동으로 인덱스를 만든다.

인덱스의 장점
1. SELECT 속도가 향상된다
- 검색조건에 INDEX가 있으면 조회 속도가 빨라질 수 있다.
2. ORDER BY 성능 향상
- 정렬을 빠르게 할 수 있다.

인덱스의 단점
1. 저장공간이 추가로 필요하다.
- 인덱스는 별도의 자료구조이기 때문에 테이블 데이터를 저장하는 곳 외에 인덱스 공간이 추가로 필요하다.
2. INSERT가 느려질 수 있다.
- 데이터를 추가할 때 테이블에만 넣는 것이 아니라 인덱스도 같이 갱신해야 한다.
3. UPDATE가 느려질 수 있다.
- 인덱스가 걸린 컬럼을 수정하면 인덱스도 다시 정리해야 한다.
4. DELETE가 느려질 수 있다.
- 데이터를 삭제할 때도 인덱스에서 해당 값을 정리해야 한다.

인덱스를 걸면 좋은 컬럼
1. WHERE 조건에 자주 사용되는 컬럼
2. JOIN에 자주 사용되는 컬럼
3. ORDER BY에 자주 사용되는 컬럼
4. GROUP BY에 자주 사용되는 컬럼

인덱스를 걸면 애매한 컬럼
- 값의 종류가 너무 적은 컬럼

단일 컬럼 인덱스
- 하나의 컬럼에 만드는 인덱스
CREATE INDEX idx_employee_department ON employee(department)

복합 인덱스
- 여러 컬럼을 묶어서 만드는 인덱스
CREATE INDEX idx_employee_dept_salary
ON employee(department,salary)

내가 작성한 SELECT 문장이 INDEX를 사용하는지 확인하는 방법
문장 앞에 EXPLAIN 작성

조회를 빠르게 하기 위한 목적으로 사용
- where, order by, group by에 많이 사용되는 속성에 대해 미리 접근 위치를 기록해놓는 것
- 실제 조회를 할 때 해당 컬럼이 사용되면 index가 자동으로 사용
- insert, update, delete에 대해선 다소 불리

create index 인덱스명 on 테이블(컬럼)

SHOW INDEX FROM 테이블명

DROP INDEX 인덱스명 ON 테이블명

Sub Query - DML의 활용
- SQL문 안에 SQL문이 있는 것
- 특정 조건을 다른 테이블의 조회 결과로 판단할 때
평균값, 최대값 같은 계산 결과를 기준으로 조회할때
- join 없이 단계적으로 데이터를 조회하고 싶을때

사용하는 기호
IN : 여러 값 중 하나
ANY : 하나라도 만족
ALL : 모두 만족

종류
- 단일행 서브쿼리 : 결과가 1개
- 다중행 서브쿼리 : 결과가 여러개
- 다중컬럼 서브쿼리 : 컬럼이 여러개
- 상관 서브쿼리 : 바깥 쿼리와 연결
- from절 서브쿼리 : 가상 테이블처럼 사용

Join - DML의 활용
- 정규화를 통해서 분리된 테이블에서 공통된 컬럼을 기준으로 연결해서 조회하는 기능

INNER JOIN
- 두 테이블에서 조건이 일치하는 데이터만 조회

LEFT OUTER JOIN
- 왼쪽 테이블(FROM절에 작성된 테이블)의 데이터는 전부 조회, 오른쪽 테이블(JOIN된 테이블)의 데이터는 조건이 맞는
데이터만 조회
- 없는 데이터 쪽은 NULL로 표시한다.

RIGHT OUTER JOIN
- 오른쪽 테이블은 전부 조회, 왼쪽 테이블은 조건이 맞는 데이터만 조회
- LEFT와 RIGHT는 방향만 바뀐 것이기 때문에 테이블 순서를 바꿔서 LEFT를 많이 사용함

CROSS JOIN
- 두 테이블에 들어있는 데이터의 모든 조합을 만든다.

핵심 문법
SELECT 조회하고 싶은 컬럼
FROM 기준 테이블 별칭
JOIN 연결 테이블 별칭
ON 기준 테이블.컬럼 = 연결테이블.컬럼;
ON 절이 구별하는 기준

외래키가 없어도 조인은 가능하나 무결성을 해칠 수 있기 때문에
권장하지 않는다.

두 테이블에 같은 이름의 컬럼이 있으면 어느 테이블에서 조회하려는 것인지 명확하게 작성을 한다.
employee.emp_id,enroll.emp_id

View - DDL의 활용

복잡한 SELECT문을 간단하게 저장할 수 있는 효과
VIEW를 만든다고 해서 실제로 데이터가 저장되는것은 아니다.
원본데이터가 바뀌면 VIEW에 들어있는 데이터도 바뀐다.
VIEW 안에서 VIEW를 사용하는 것이 가능하긴 하나 성능 저하 발생할 수 있음

본인이 만들어보고싶은 서비스가 있을 때
ㄴ 모델링을 잘 하고, 테이블을 잘 만들고, 어떤 데이터를 조회해서 보여줘야할지를 고민해서 결정

AUTO_INCREMENT
- 숫자 값을 자동으로 1씩 증가시켜서 입력해주는 속성
- 데이터를 추가할 때마다 직접 번호를 입력하면 번거롭기 때문에 사용한다.
- 반드시 숫자 타입의 컬럼에만 붙여야 한다
- 한 테이블에 하나만 사용할 수 있다.
- 직접 값을 넣을 수도 있다.
INSERT INTO board(board_id,title,content)
values (100,'관리자 공지','직접 번호 입력');
그 다음 자동 증가 값은 보통 101부터 시작한다.
- 중간 번호는 재사용하지 않는다.
- AUTO INCREMENT는 연속 번호 보장용이 아닌 고유 식별자 생성용이다.
- INSERT 했다가 ROLLBACK 해도 다음 번호로 건너뛴다.
- 테이블 생성 수 다음 자동 증가값을 바꿀 수 있다.
ALTER TABLE 테이블명 AUTO_INCREMENT = 1000;
이후 새 데이터는 1000부터 들어갈 수 있다.

- 현재 AUTO_INCREMENT 값 확인하기
SHOW TABLE status LIKE '테이블명';

LIMIT
- 조회 결과를 제한하는 절
- 몇개까지만 보여줘
SELECT * FROM 테이블 LIMIT 개수;

ORDER BY와 함께 많이 사용된다.
내림차순으로 정렬해서 상위 5개만 조회해라
데이터가 몇백만건 들어있는 테이블에서 LIMIT이 없으면 위험할 수 있다.

LIMIT 시작위치,개수
LIMIT 개수 OFFSET 시작위치

페이징 처리할때 사용
SELECT * FROM BOARD ORDER BY BOARD_ID DESC LIMIT 0,10;
0개 건너뛰고 10개 조회

SELECT * FROM BOARD ORDER BY BOARD_ID DESC LIMIT 10,10;
10개 건너뛰고 10개 조회
