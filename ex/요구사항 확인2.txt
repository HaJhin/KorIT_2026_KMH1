요구사항의 시스템화 타당성 분석
- 적용하려는 기술의 적합성 및 기술 실현 가능성에 대한 분석

성능 및 용량 산정 적정성 -> 시스템 간 상호 운용성 -> IT 시장 성숙도 및 트렌드 부합성 -> 기술적 위험 분석

성능 및 용량 산정 적정성
예상 사용량 (사용자수 - 데이터의 양 - 트랜잭션 처리량)을 과거 만들었던 프로젝트와 비슷하게 설정을 해놓고,
성능 관련 비기능 요구사항을 충족하는지 판단하는 과정

1. 예상 용량 산정
2. 유사 프로젝트 경험치 적용
3. 재조정
4. 비기능 요구사항과 비교
5. 적정성 판단
6. 미충족시 개선 방안 검토
7. 다시 용량 산정
8. 충족 여부 재검토

시스템 간 상호 운용성
- 나의 시스템과 외부 시스템 간의 정상적으로 동작할 수 있는지 분석

연동대상 시스템을 확인
- 우리 시스템이 어떤 외부 시스템과 연결되어야하는지 확인
예시) 결제 API, 택배 API, 문자발송 API ...
시스템명 : 어떤 시스템과 연결하는가
담당기관 : 누가 운영하는가
연동 목적 : 왜 연결하는가
제공 기능 : 어떤 기능을 제공하는가
운영 시간 : 언제 사용 가능한가
장애 대응 연락처 : 문제 발생 시 누구에게 문의하는가

정보 교환 가능 여부 확인
- 우리 시스템과 외부 시스템이 실제로 데이터를 주고 받을 수 있는지
API : 외부 시스템이 데이터를 받을 수 있는 창구 제공
데이터 형식 : 어떤 형태로 데이터를 주고받는가(JSON)
인증방식 : 아무나 접근이 가능한가, 인증이 필요한지
네트워크 접근 : 우리 서버에서 외부 시스템에 접근이 가능한가
필수 데이터 : 요청할 때 어떤 값이 필요한가
응답 데이터 : 결과로 어떤 값을 받을 수 있는가

서비스 제공 방식 확인
- 외부 시스템이 어떤 방식으로 서비스를 제공하는지 확인
- 정보 교환이 가능하더라도 제공 방식이 다르면 요구사항을 만족하지 못할 수 있다.
제공 주기 : 얼마나 자주 데이터가 갱신되는가
제공 방식 : 요청하면 주는가, 정해진 시간에 주는가
응답 속도 : 요청 후 얼마나 빨리 응답하는가
이용 제한 : 호출 횟수 제한이 있는가
장애 시 처리 : 장애가 나면 어떻게 되는가
운영 시간 : 24시간 제공되는가

연동 가능 여부 판단
- 앞에서 확인한 내용을 바탕으로 실제로 연동 가능한지 최종 판단
연동 가능 : 요구사항대로 구현 가능
조건부 가능 : 추가 작업을 하면 가능
연동 불가능 : 현재 요구사항대로 구현 불가

IT 시장 성숙도 및 트렌드 부합성
- 필요한 기술이 현재 시장에서 얼마나 안정적으로 사용되고 있는지
- 앞으로 계속 발전할 가능성이 있는지

사용할 기술 확인
- 기술이 정해져야 좋은지 나쁜지 알 수 있다.


시장 성숙도 확인
- 선택한 기술이 얼마나 검증되었는지 확인
- 이 기술을 다른 회사도 많이 쓰는가?
출시된 기간
사용 기업 수
개발자 수
자료 수
기술 지원

성숙도가 낮으면 오류 발생 -> 검색 -> 해결방법 없음 같은 문제가 생길 수도 있다.

기술 발전 방향 확인
- 현재뿐 아니라 앞으로 기술이 어떻게 발전할 것인지 확인
사용량 증가 여부
기업 도입 증가 여부
새로운 기능 추가 여부
시장 성장 여부

요구사항 적합 여부 판단
- 이 기술이 우리 시스템 요구 사항을 만족하는가?

기술적 위험 분석
- 요구사항을 구현하기 위해 사용할 기술이 문제를 일으킬 가능성이 있는지, 문제가 생겼을때 영향이 얼마나 큰지 판단

복잡성
- 기술이 너무 복잡하거나 우리 시스템 구조와 맞지 않아 문제가 생길 가능성

검증 여부
- 이 기술이 이미 많이 사용되어 믿고 쓸 수 있는가?

의존성
- 이 기술이나 업체가 없으면 우리 시스템이 계속 운영되기 어려운가?
특정업체 기술에 의존 -> 업체에 문제가 생기면 서비스에도 문제가 생긴다.
특정 라이브러리만 사용 -> 사용자가 증가되서 라이선스 비용이 증가하면 예상 비용이 증가한다.
의존성의 위험이 증가한다.
